## R2 재정의 — 구현자에서 차가운 검토자로 (2026-09-10)

### 왜 바꾸나

| 사실 | |
|---|---|
| 담당 스펙 7건 **전부 완료** | A12 제거 · A15~A20 검증 완료 → **원래 역할이 소멸했다** |
| 소유 파일 경계가 **이미 무너졌다** | `style.css` 최근 커밋 7개가 전부 조율자 것(A30·A31·A32 등) |
| 워크트리가 **11개 머지 뒤처져 있었다** | 그 상태로 리뷰를 돌려 **이미 고친 P1 2건을 다시 지적**했다 |
| 그런데도 **진짜 결함 3건을 찾았다** | 리포트 CTA 주제 어긋남 · 폴백 업종 점 먹통 · README 토큰값 |

마지막 줄이 핵심이다. **P2 CTA 버그는 내가 쓴 코드고 나는 못 봤다.** 낡은 코드를 보고도 찾아냈다. 그게 차가운 독자만 가진 값이고, R2를 없애지 않는 이유다.

반대로 **구현자로 두면 손해다.** 같은 파일을 둘이 만지면 충돌 관리 비용이 병렬화 이득을 넘는다 — 이 문서가 원래부터 말하던 바로 그 이유다.

### 규칙 4개

1. **첫 동작은 동기화다.** `git fetch origin && git merge --ff-only origin/main`. 이번 사고의 **유일한** 원인이 이걸 안 한 것이다.
2. **본 커밋 SHA를 반드시 적는다.** 지적 목록 맨 위에 `reviewed: <sha>`. 없으면 낡음을 판별할 수 없다 — 이번에도 SHA가 있었으면 5분 만에 걸렀다.
3. **코드를 고치지 않는다.** 지적만 하고 수정은 조율자가 한다. 이번에 실제로 그렇게 굴러갔고 잘 됐다. 고치기 시작하면 무너진 경계를 다시 세워야 한다.
4. **전체 훑기 대신 diff를 준다.** 범위를 `origin/main~N..origin/main`으로 좁힌다. 전체 정적 검토는 이미 고친 것을 반복 지적하고, 그 소음이 진짜 3건을 묻는다.

### 검토 요청 형식

```
범위: <base>..<head>
확인해 주세요:
  - 이 diff가 깨뜨리는 기존 동작
  - 문서(docs/decisions.md·design-system.md)와 어긋나는 구현
  - 테스트가 없는 분기
답변에 reviewed: <sha> 를 첫 줄에 적어 주세요.
```

### 대안 — 없애는 선택지

R2를 접고 워크트리를 지우는 것도 정직한 선택이다. **남은 작업이 거의 없어서** 검토할 diff 자체가 드물기 때문이다. 다만 이번에 3건을 건졌으니 **다음 큰 변경(예: A4a 답변 품질) 때까지는 두고** 그때도 소득이 없으면 접는다.

## 나누는 기준

**기술 스택이 아니라 파일 소유권으로 나눈다.** 두 에이전트가 같은 파일을 고치면 병합 충돌이 나고, 충돌 해결 비용이 병렬화 이득을 넘는다.

그래서 각 브리핑에는 **소유 파일**과 **건드리지 않을 파일**이 명시돼 있다. 소유하지 않은 파일이 필요하면 소유 역할에 요청한다.

## 도구가 섞일 때 (코덱스 참여)

R2를 코덱스가 맡는다. **다른 도구의 에이전트는 이 대화 맥락 없이 차갑게 시작한다.** 그래서 세 가지를 지킨다.

1. **브리핑이 자기완결적이어야 한다** — R2 브리핑에는 근거뿐 아니라 **현재 상태 실측값과 정확한 목표 값**이 들어 있다. "왜"를 모르고도 작업할 수 있어야 한다.
2. **수용 기준은 파일에서 확인 가능해야 한다** — 브라우저 검증이 어려울 수 있으므로, 가능한 항목은 `grep`으로 확인 가능한 형태로 적었다(예: "색상 리터럴이 `:root` 밖에 없다").
3. **교차 도구 인계를 최소화한다** — 아래 경계 조정 참조.

### 코덱스 참여로 조정한 경계

| 항목 | 원래 | 조정 | 이유 |
|---|---|---|---|
| **A12** 기준 배지 | R1 마크업 → R2 톤 | **R2 단독** | 정적 요소라 JS가 없다. 인계를 하나 없앤다 |
| **A16** 웹폰트 | R2, 순서 미정 | **R2가 가장 먼저** | `<head>`만 건드리는 소규모 작업. R1이 `<body>`를 만지기 전에 끝내면 `index.html` 경합이 사라진다 |
| **A19** 증감 색 | R2 단독 | **R2가 클래스 계약 정의 → R1이 마크업 적용** | 색은 CSS지만 증감 값을 감싸는 `<span>`은 JS가 만든다. 나눌 수밖에 없다 |

## 경계 충돌 — 미리 정해둘 것

### ① `frontend/index.html` — R1과 R2가 함께 만진다

| 구역 | 소유 |
|---|---|
| `<head>` (폰트 로드 · 메타 · `<title>`) | **R2** |
| `<body>` 구조 · 새 요소 | **R1** (단, A12 배지는 R2) |

**R2의 A16을 가장 먼저 끝내면 이 충돌은 사실상 사라진다.**

#### 삽입 순서 — A12 배지와 A9 목적 칩은 같은 지점을 노린다

A12는 "주제 버튼 **바로 위** 배지", A9는 "주제 버튼 **위에** 목적 칩"이라 **둘 다 `#topic-list` 직전**이 목표다. 순서를 미리 못 박는다.

```html
<div class="pane-header">   <!-- 기존 -->
<div class="topic-basis">   <!-- A12 배지 · R2 -->
<div class="purpose-chips"> <!-- A9 목적 칩 · R1 -->
<div id="topic-list">       <!-- 기존 -->
```

**A12가 위, A9가 아래다.** A12는 화면 전체에 걸리는 전제(무슨 데이터이고 무엇이 없는지)이고, A9는 행동 유도라 주제 버튼에 붙어 있어야 한다. 배지를 칩 아래 두면 "칩 → 주제 버튼" 시선 흐름을 가로막는다.

#### A12는 R1 영역을 하나 지운다 — 허가된 예외

A12는 **승격**이므로, R2가 배지를 만들면서 `frontend/index.html`의 `<p class="topics-foot">` 줄을 **함께 제거한다.** 이 줄은 `<body>`라 원칙상 R1 소유지만, 배지만 추가하고 각주를 남기면 같은 내용이 화면에 두 번 나온다.

**R2에 허가된 `<body>` 편집은 이 둘뿐이다** — A12 배지 신설 · `.topics-foot` 제거. R1은 이 줄을 건드리지 않는다.

### ② A14(주제 리포트) — R3와 R1

- **R3**: 4블록(요약/핵심 수치/해석/한계)을 강제하는 **시스템 프롬프트** + 요청 경로 설계
- **R1**: CTA 버튼 · 응답 렌더

**R3가 요청 방식(별도 엔드포인트 vs `context` 플래그)을 먼저 정해 R1에 알린다.**

### ③ A19(증감 색) — R2와 R1

- **R2**: `.trend-up` / `.trend-down` 클래스와 색 정의
- **R1**: 수치 헤드라인에서 증감 부분을 해당 클래스로 감싸는 마크업

### ④ A21(대기 상태) — R1과 R5

- **R1**: 경과 시간 타이머 + 단계적 문구 갱신
- **R5**: F3 에러 3종 분기 유지 및 **문구 정확성 수정**

**문구 소유권은 R5, 타이머 동작은 R1.** 현재 `cold` 문구가 "다시 시도해 주세요"인데 실제로는 자동 완료된다 — **두 역할이 같은 문구를 서로 다르게 고치면 안 된다.**

## 공통 규칙 (전 역할)

1. **소유하지 않은 파일을 고치지 않는다.** 필요하면 소유 역할에 요청한다.
2. **스펙 ID를 커밋 메시지에 넣는다** — `feat: A9 목적 칩을 추가한다`. 폐기 번호(A3a·A5·D1·D2) 재사용 금지.
3. **진행 상태는 [`../roadmap.md`](../roadmap.md)에만 쓴다.** 스펙 파일에 상태를 적지 않는다.
4. **[`../decisions.md`](../decisions.md)의 결정 완료 항목을 재논의하지 않는다.**
5. **수용 기준 충족 여부를 스스로 확인하고 보고한다.** 미달이면 미달이라고 쓴다.
6. **문서를 고치면 [`../CHANGELOG.md`](../CHANGELOG.md)에 한 줄 남긴다.**
7. **비밀 정보 금지** — `.env` · `firebase-service-account.json`은 커밋도 값 노출도 하지 않는다.
8. **사용자에게 보이는 텍스트는 한국어.**
9. **`main`은 배포 대상이다.** 검증 전 작업은 별도 브랜치에서.
