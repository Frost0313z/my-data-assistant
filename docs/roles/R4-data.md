## B2 요점

### 반드시 지킬 것

**1. 배치 쓰기** — Firestore `batch`, 500건 단위. 단건 쓰기로는 규모를 감당 못 한다.

**2. 재실행 안전(upsert)** — 대량 적재는 중간 실패가 잦다. **upsert가 아니면 재시도할 때마다 중복이 쌓인다.** 이게 B2의 핵심 수용 기준이다.

**3. 수치 출처 일원화** — `frontend/js/topics-data.js`와 `backend/app/seed/insights.md`가 **같은 출처를 써야 한다.** 한쪽만 고치면 화면과 AI 답변의 숫자가 어긋난다.

**수용 기준**: `/api/data`가 실제 상권 레코드를 페이지네이션으로 반환하고, 필터별 요약이 의미 있는 값을 낸다. **재실행해도 중복 적재되지 않는다.**

### B2가 바꾸는 것 — 후속 역할에 알릴 것

| 영향 | 무엇이 바뀌나 | 소유 |
|---|---|---|
| **C5** 요약 캐시 | 매 채팅마다 전량 집계는 비현실적 → **필수가 된다** | R3 |
| **D3** 시드 리셋 | 복구 대상이 커져 **배치 삭제·재적재**가 필요 | R3 |
| **B3** 요약 필터 | 전체 요약이 무의미해져 **필터 없이는 대화가 성립 안 됨** | R3 |

**B2 완료 시 R3에 반드시 통보한다.**

## B1 요점

현재 `insights.md`는 **수기 큐레이션**이다. 분석 저장소의 집계 CSV/노트북 출력에서 재생성하는 `scripts/build_insights.py`를 만든다.

**수용 기준**: 스크립트 실행 → `insights.md` 재생성, **수기 버전과 수치가 일치**한다.

> `insights.md`는 AI 시스템 프롬프트의 `[사전 분석 리포트]` 블록으로 통째로 들어간다. 여기 없는 내용은 AI가 "없다"고 답한다. **한계 서술("매출·유동인구 없이 점포 수만 본 분석", "흥망 단정 안 함", "업소번호 등장·소멸로 추정")을 지우지 말 것** — 이게 서비스의 차별점이다.

## 데이터 해석 원칙

작업 중 요약·문구를 쓸 일이 있으면 지킬 것.

**증감에 가치판단을 붙이지 않는다.** 우리 데이터에는 매출·유동인구가 없어서 점포 증가가 좋은 일인지 알 수 없다. 실제 반례:

- **목동** — 잔존율 최저(73.7%)인데 **+5.3% 증가**
- **대흥동** — 밀도 2위인데 **+0.4%로 정체**
- **중앙동** — 공급밀도 1위(585.3개/1,000명)인데 잔존율은 평균 이상

"좋다/나쁘다/호조/부진/유망" 어휘를 쓰지 않는다. 방향과 수치만 쓴다.

## 절대 깨뜨리면 안 되는 것

1. **비밀 정보** — `firebase-service-account.json` · `.env`는 커밋도 값 노출도 금지
2. **쓰기 요청 폴링 금지** — 진행 확인을 위해 mutating 요청을 반복하지 않는다
3. **기준선 보존** — 현재 시드는 `data` 492 레코드다. 적재 전 되돌릴 방법을 확보한다
4. **분석 저장소는 추가만** — 대시보드 HTML을 고칠 일이 있으면 **격리된 블록 추가**만 하고 기존 로직을 바꾸지 않는다. 파라미터 없이 열면 기존과 동일하게 동작해야 한다
