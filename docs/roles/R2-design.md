## 이 프로젝트가 뭔지 (30초)

대전 상권 데이터를 **AI가 설명해주는** 웹앱. 바닐라 HTML/CSS/JS(빌드 도구 없음) + FastAPI 백엔드.

화면은 **3분할**이다.

```
┌─────────┬──────────────────┬──────────┐
│ 사이드바 │  분석 주제 패널    │  AI 채팅  │
│ 288px   │  (대시보드 임베드)  │  400px   │
│ 요약·기록│                   │          │
└─────────┴──────────────────┴──────────┘
     쿨 (데이터)                  웜 (대화)
```

**브랜드**: `침착한 · 솔직한 · 정확한`. 목표 감정은 **"정직한 신뢰"**.

사용자는 창업 결정을 앞두고 불안한 상태이고, 우리 데이터에는 **매출·유동인구가 없다.** 그래서 확신을 연출하면 거짓말이 된다. **차분하고, 자기 주장하지 않고, 근거를 가리키는** 화면을 만든다.

## 담당 스펙

**작업 순서는 A16 → A12 → (Wave 2) A15 → A17 → A18 → A19 → A20.**

### A16 — 웹폰트 로드 + 수치 타이포 · P1/S · **최우선**

> 이걸 가장 먼저 하는 이유: `<head>`만 건드리는 소규모 작업이라, R1이 `<body>`를 만지기 전에 끝내면 `index.html` 경합이 사라진다.

- `Pretendard` 웹폰트를 **실제로 로드**한다 (CDN 링크 또는 `@font-face`)
- 웨이트는 **400 / 500 / 600만** 사용 — 700 남용 금지(차분함)
- `font-variant-numeric: tabular-nums`를 **헤드라인 수치·요약·표로 확대** (현재 `.usage`에만)

**수용 기준**: 의도한 서체가 실제로 렌더된다. 자릿수가 다른 숫자들이 세로로 정렬된다.

### A12 — 기준 배지 + 한계 고지 · P1/S

현재 중앙 칸 **하단**에 회색 각주(`.topics-foot`)로 있는 내용을 **주제 버튼 바로 위 배지**로 승격한다. 마크업까지 이 역할이 만든다.

```
2025-03 → 2026-06 · 대전 82개 행정동 · 등록 업소 수
매출·유동인구 미포함 · 참고용
```

**승격이므로 원본을 지운다.** `frontend/index.html`의 `<p class="topics-foot">…</p>` 줄과 `style.css`의 `.topics-foot` 규칙을 함께 제거한다. 배지만 추가하고 각주를 남기면 같은 내용이 화면에 두 번 나온다. 이 `<p>`는 `<body>`라 원칙상 R1 소유지만 **이 건은 허가된 예외다.**

**삽입 위치 — R1의 A9 목적 칩과 같은 지점을 노린다.** 순서는 이미 확정돼 있으니 그대로 따른다.

```html
<div class="pane-header">   <!-- 기존 -->
<div class="topic-basis">   <!-- ← A12 배지. 여기 -->
<div class="purpose-chips"> <!-- 나중에 R1이 A9 칩을 넣는다. 비워둘 것 -->
<div id="topic-list">       <!-- 기존 -->
```

**배지가 위, 목적 칩이 아래다.** 배지는 화면 전체에 걸리는 전제라 위, 칩은 행동 유도라 주제 버튼에 인접해야 한다. **`.purpose-chips`는 R1이 만든다 — 미리 만들지 않는다.**

**색은 회색이 아니라 앰버(`--caution`)다.** 이유:

| 색 | 읽히는 뜻 |
|---|---|
| 빨강 | 에러 / 위험 |
| **회색** | **안 읽어도 됨** ← 현재 |
| **앰버** | **읽어라** ← 목표 |

우리의 최대 차별점은 "한계를 먼저 말하는 것"인데, 그게 지금 화면에서 **가장 흐린 회색**으로 그려져 있다. 정확히 뒤집혀 있다.

**금지**: 이 배지를 접기/닫기 가능하게 만들지 않는다. 상시 노출이 목적이다.

**수용 기준**: 데이터 기준 시점과 한계가 스크롤 없이 항상 보이고, 무시해도 되는 각주로 읽히지 않는다.

### A15 — 디자인 시스템 토큰 · P1/M · **Wave 2**

`:root` CSS 변수를 도입하고 하드코딩을 전면 치환한다. **토큰 정의와 치환 대응표가 [`../design/design-system.md`](../design/design-system.md) §4에 그대로 있다. 복사해서 쓰면 된다.**

핵심 3가지:

**(1) `#2563eb`의 5중 역할 분해** — 파란색이 흔해지면 강조력을 잃는다.

| 갈래 | Primary 사용 | 개수 |
|---|---|---|
| **액션** (누르면 뭔가 일어남) | 배경 | **화면당 1개** — 나머지 버튼은 `Surface + Line` 중성 |
| **선택 상태** (주제 버튼 active) | 배경 | 단일 선택이라 자연히 1개 |
| **정체 표시** (사용자 발화 버블) | 배경 | **제한 없음** — 누를 수 없으므로 액션과 경쟁하지 않는다 |
| **링크** | 텍스트 | 제한 없음 |

> 주제가 선택된 상태에서는 주변 액션 버튼("이 주제로 AI에게 질문", "전체 대시보드에서 보기")을 **중성으로 내린다.** 선택 상태와 액션이 같은 색이면 어느 쪽을 눌러야 하는지 구분되지 않는다.

**(2) 타입 위계 복구**

```
Display   28px / 600   핵심 수치 헤드라인   ← 현재 16.8px
H1        22px / 600                      ← 현재 17.6px
H2        18px / 600                      ← 현재 15.2px
H3        16px / 500
Body      15px / 400
Caption   13px / 400
```

**(3) 간격 · 라운드 · 그림자**

```
간격   base 4px — 스텝 4·8·12·16·24·32
라운드 버튼·입력 8 / 데이터 패널 10 / 채팅 버블 16 / 칩 999
그림자 평면 요소는 없음(1px Line으로만). 모달·드롭다운에만 0 4px 16px rgba(22,25,29,.10)
```

> 그림자는 **더하지 않기로 결정**한 항목이다. 현재 전부 보더 구분인데 이미 `차분함`에 맞다.

**수용 기준**: 화면에서 파란 요소는 선택 상태·정체 표시·링크뿐이고, 핵심 수치가 가장 크게 읽힌다. **`style.css`에 색상 리터럴이 `:root` 밖에 남지 않는다.**

### A17 — 채팅 영역 온기 분리 · P2/S

3분할의 **좌·중앙(쿨) / 우 채팅(웜)** 감성 분업. 현재 AI 버블이 무채색 `#eef0f3`이라 어시스턴트가 **시스템 메시지처럼** 보인다.

- AI 버블 배경 → `--warm-050 #FBF7F1`, 경계 `--warm-300 #E6D9C6`
- 버블 라운드 12 → **16px**

> 주의: `#eef0f3`은 제안 질문 칩·표 버튼에도 쓰인다. **AI 버블만** 웜으로 바꾸고 나머지는 `--surface-sunken`으로 보낸다.

### A18 — 모션 원칙 도입 · P2/S

**현재 모션이 0이다.** 줄이는 게 아니라 **필요한 곳에만 더하는** 작업이다.

```
--motion-feedback   120ms  ease-out       버튼·칩 눌림, 호버
--motion-fade       150ms  ease-out       주제 패널 교체, 상태 오버레이
--motion-pane       200ms  ease-in-out    모바일 탭 전환
그 외              없음
stagger            사용하지 않음
등장 애니메이션      쓰지 않음 (3분할 화면에서 소음)
```

**Delight(confetti·바운스) 전면 배제.** 사용자가 얻는 결과는 "성공한다"가 아니라 "점포 수로 본 방향, 매출은 모름"이다. 축하 연출을 붙이면 보증할 수 없는 것을 보증하는 연출이 된다. **리포트 생성 완료에도 넣지 않는다.**

주제 버튼에 `scale`·`translate` 금지 — 버튼이 움직이면 8개 그리드가 흔들려 보인다.

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

상세는 [`../design/motion.md`](../design/motion.md).

### A19 — 증감 표현 중립 색 · P1/S · **R1과 분담**

**증감에 초록/빨강을 쓰지 않는다.**

```
--trend-up    #2F5FA8  (Cool)   증가
--trend-down  #B06A2C  (Warm)   감소
```

관습은 `증가=초록(좋음)`이지만 **우리는 그 판단을 할 수 없다.** 매출이 없어서 점포 증가가 좋은 일인지 모른다. 실제 반례가 있다 — **목동은 잔존율 최저(73.7%)인데 +5.3% 늘었고, 대흥동은 밀도 2위인데 +0.4%로 멈췄다.** 초록/빨강은 이 뉘앙스를 지운다.

**이건 장식이 아니라 브랜드 약속의 시각적 구현이다.**

**분담**: 이 역할은 `.trend-up` / `.trend-down` **클래스와 색만 정의**한다. 증감 값을 감싸는 `<span>` 마크업은 JS가 만들므로 **R1이 적용한다.** 클래스 이름을 정하면 R1에 알린다.

## 절대 깨뜨리면 안 되는 것

기존에 실제로 문제가 났던 부분이다.

### 1. `[hidden]` 전역 리셋

```css
[hidden] { display: none !important; }
```

`style.css` 상단에 있다. **지우지 말 것.** 독립 HTML에는 이 UA 스타일 보정이 없어서, 작성자의 `display:flex` 같은 규칙이 `hidden` 속성을 덮어버린다. 탭바와 로딩 오버레이가 안 숨겨지는 문제가 실제로 있었다.

### 2. 페이지 스크롤 구조

```css
.layout { min-height: 100vh; align-items: start; }   /* height:100vh + overflow:hidden 금지 */
.sidebar, .chat-pane { position: sticky; top: 0; height: 100vh; }
```

`height:100vh; overflow:hidden`으로 되돌리면 **문서 스크롤이 잠긴다.** 그러면 커서가 임베드 iframe 위에 있을 때 휠 이벤트를 뺏겨 **스크롤이 죽은 것처럼 보인다.** 실제로 발생했던 버그다.

### 3. 임베드 대시보드는 다크로 유지

중앙 칸 iframe(`--viewport-bg #0F1319`)은 외부 저장소(GitHub Pages)의 대시보드라 **우리가 팔레트를 못 바꾼다.** 밝게 만들려 하지 말 것. 대신 **라운드·여백으로 "의도된 데이터 뷰포트"처럼 액자화**한다.

빌드 도구가 없다. 정적 서버로 열면 된다.

```bash

grep -o '[0-9]\+ms' frontend/css/style.css | sort -u
```
