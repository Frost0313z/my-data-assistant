## 항목별 요점

### E1 — 아키텍처 구성도

현재 README에는 **시퀀스 다이어그램만** 있다. 시스템 구성도를 추가한다.

```
브라우저 ─ Vercel(정적) ─ Render(FastAPI) ─ Firestore
                │                    └─ OpenAI gpt-4o-mini
                └─ GitHub Pages (대시보드 iframe, 별도 저장소)
```

**수용 기준**: 그림 하나로 배포 토폴로지와 데이터 흐름이 보인다.

### E5 — README 재구성

**차별점을 앞세운다.** 이 프로젝트의 기술적 핵심은 **3블록 컨텍스트 주입**이다.

1. `[실시간 데이터 요약]` — 매 요청 재계산
2. `[사전 분석 리포트]` — `insights.md` 고정 스냅샷
3. `[선택한 분석 주제]` — 사용자가 화면에서 고른 주제

파인튜닝도 RAG도 아닌 **컨텍스트 주입**을 택한 판단이 서사의 중심이다.

### E2 — ADR

가장 좋은 후보 5개:

1. **컨텍스트 주입 vs 파인튜닝/RAG**
2. **대시보드 임베드 vs 이식(재구현)**
3. **증감 색 중립화** — 제품 판단이 시각 규칙이 된 사례. 가장 독특하다
4. **인증 제외** — 범위를 좁혀 서사를 세운 판단
5. **바닐라 JS 채택**

각 ADR에 **맥락 · 결정 · 트레이드오프 · 대안**을 적는다.

### E3 — 데모

`주제 선택 → 패널 확인 → 질문 → AI가 그 주제 기준으로 답변 → 리포트` 흐름 녹화.

> **주의**: 콜드스타트가 있으면 첫 응답이 40초 넘게 걸린다. **녹화 전 워밍업**하거나 그 구간을 편집한다.

**수용 기준**: README를 열면 30초 안에 무엇을 하는 도구인지 보인다.

### E4 — 회고

배운 점, 트레이드오프(무료 티어 제약·컨텍스트 주입 한계), 다음 단계.

**솔직하게 쓴다** — 브랜드가 `솔직한`인데 회고에서 포장하면 앞뒤가 안 맞는다. 실제로 설계를 세 번 바꿨고(전체 임베드 → 주제 버튼 → 섹션 임베드), 문서 점검에서 결함도 나왔다. 그런 게 재료다.

### docs/ 정합성 유지 (상시)

분할 구조라 **중복이 갈라지는 것**이 최대 위험이다. 두 규칙을 지킨다.

- **진행 상태는 [`../roadmap.md`](../roadmap.md)에만** — 스펙 파일에 상태를 적지 않는다
- **디자인 구현 값은 [`../design/design-system.md`](../design/design-system.md)에만** — 나머지는 링크로 참조

**주기 점검** (다른 역할이 작업을 끝낼 때마다):

```bash
cd docs
# 링크 검사
for f in $(find . -name "*.md"); do d=$(dirname "$f"); \
  grep -o '](\.\{1,2\}/[^)]*)' "$f" | sed 's/^](//; s/)$//; s/#.*//' | \
  while read -r l; do [ -e "$d/$l" ] || echo "BROKEN: $f -> $l"; done; done

# 스펙 ID가 어느 Phase에도 없는지 (A6가 이렇게 누락됐었다)
```

## 절대 깨뜨리면 안 되는 것

1. **스펙 ID 불변** — 폐기된 `A3a` · `A5` · `D1` · `D2` 번호를 재사용하지 않는다
2. **결정 완료 항목 재논의 금지** — 뒤집을 근거가 생기면 지우지 말고 **새 결정을 추가**한다
3. **비밀 정보 금지** — `.env` 내용, 서비스 계정 JSON, API 키를 문서·스크린샷에 노출하지 않는다. **데모 영상에 개발자 도구를 열지 않는다**
4. **한국어** — 사용자에게 보이는 텍스트는 한국어
5. **v1.0 기준선 표를 지우지 않는다** ([`../context.md`](../context.md)) — 회귀 확인 기준이다
