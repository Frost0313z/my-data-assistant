## Wave 1 — F3 문구 결함 (최우선)

**현재 안내가 틀렸다.**

`frontend/js/chat.js`의 `showErrorBubble`:

```
cold: "백엔드가 잠들어 있어 깨우는 중입니다. 무료 플랜이라 최대 50초 걸릴 수 있어요.
       잠시 후 다시 시도해 주세요."
```

**실제 동작**: Render 무료 티어는 15분 유휴 후 스핀다운되지만, 이후 첫 요청을 **붙잡아둔 채 완료시킨다**(실측 43초). `fetch`에 기본 타임아웃이 없어 **자동으로 성공한다.**

즉 **재시도를 권하는 것이 오안내다.** 사용자는 기다리기만 하면 된다.

**고칠 것**
- 대기 중에는 "**기다리면 된다**"고 말한다 (문구는 R1의 A21 타이머가 표시)
- **진짜 실패했을 때만** 재시도를 권한다
- `classifyError`가 `Failed to fetch`를 `cold`로 분류하는데, **로컬 CORS 실패도 같은 메시지를 낸다.** 실제로 이 때문에 CORS 문제를 콜드스타트로 오진한 적이 있다 — 분류 정확도를 높이거나 문구를 중립적으로 바꾼다

> **소유권 경계**: 문구 문자열은 이 역할, **타이머 동작은 R1**. 같은 문구를 서로 다르게 고치지 않도록 R1과 맞춘다.

**F3의 나머지 책임**: 진짜 실패 시 3종 분기(콜드스타트/무응답 · OpenAI 실패 · 일반) + 재시도 유지.

## 항목별 요점

### C1 — pytest 스위트

현재는 `backend/tests/` pytest 스위트다(C1 완료). `pytest` 기반으로 옮기고 라우터별 통합 테스트(`TestClient`)를 추가한다. **Firestore·OpenAI는 페이크/모킹** — 실제 호출 금지(비용·쓰레기 데이터).

**반드시 덮을 회귀 케이스** (실제로 검증했던 것):

| 입력 | 기대 |
|---|---|
| `Inf` · `NaN` 값 | 422 |
| 범위 초과 값 | 422 |
| 잘못된 날짜 형식 | 422 |
| 빈 메시지 | 422 |
| `context`에 허용되지 않은 키 | 무시 (`CONTEXT_KEYS = {"topic", "mode", "persona", "regionType"}`) |
| `/api/data/summary` 정상 | 200 |

### C2 — CI

푸시·PR마다 `pytest` + 프론트 `node build.js` 스모크. **통과 시에만 배포.**

### C6 — 콜드스타트 핑

외부 크론(cron-job.org 등)으로 10분마다 `/` 핑.

> **`GET /`만 쓴다.** 워밍업 목적으로 **쓰기 요청을 폴링하지 않는다** — 과거 Firestore에 쓰레기 레코드가 쌓였다.

### F1 — 접근성 · **A15 선행 필수**

키보드 내비게이션, ARIA 라벨, **색 대비 AA**, 채팅 새 메시지 시 포커스·`aria-live`.

**A15(디자인 토큰) 완료 후에 시작한다.** 팔레트가 바뀌는데 먼저 검증하면 두 번 일한다.

A15 이후 대비를 특히 확인할 값:

| 전경 / 배경 | 용도 |
|---|---|
| `--ink-500 #6B7280` / `--canvas #F6F7F9` | 보조 텍스트 |
| `--ink-400 #8B93A1` / `--surface #FFFFFF` | 토큰 사용량 (13px) |
| `--caution #8A5A00` / `--caution-bg #FDF6E7` | 한계 고지 |
| `--viewport-muted #93A2B3` / `--viewport-bg #0F1319` | 임베드 로딩 문구 |

**모션 접근성**: `prefers-reduced-motion` 대응은 A18(R2) 범위지만 F1 수용 기준에도 걸린다. 다만 **대기 상태의 경과 초 표시는 줄이지 않는다** — 애니메이션이 아니라 정보다.

**수용 기준**: 키보드만으로 전체 조작, Lighthouse 접근성 90+.

### F2 — 성능

iframe 지연 로드, 정적 자산 캐시 헤더, 폰트 폴백.

> 임베드 대시보드가 **1.8MB 단일 파일**이라 초기 로드가 느린 게 정상이다. 이건 외부 저장소 자산이라 우리가 못 줄인다. **채팅은 대시보드와 무관하게 즉시 상호작용 가능해야 한다.**

**수용 기준**: Lighthouse 성능 90+.

## 절대 깨뜨리면 안 되는 것

### 1. `[hidden]` 전역 리셋

`style.css` 상단의 `[hidden] { display: none !important; }`를 지우지 말 것. 없으면 작성자 `display` 규칙이 `hidden` 속성을 덮어 탭바·로딩 오버레이가 안 숨겨진다.

### 2. 페이지 스크롤 구조

`.layout`을 `height:100vh; overflow:hidden`으로 되돌리면 문서 스크롤이 잠기고, 커서가 iframe 위일 때 휠이 먹혀 **스크롤이 죽은 것처럼 보인다.**

### 3. 테스트에서 실제 외부 호출 금지

Firestore·OpenAI는 반드시 모킹. 실제 호출은 비용이 들고 쓰레기 데이터가 쌓인다.

### 4. 테스트 데이터 정리

수동 검증 후 기준 상태로 되돌린다: **conversations 0 / data 492**.
