## 현재 구조

```
POST /api/chat        {message, conversation_id?, context?} → {conversation_id, reply, usage}
GET  /api/data        데이터 목록
GET  /api/data/summary 기간·개수·평균/최대/최소·추세
```

**시스템 프롬프트는 3블록 구성**이다.

1. `[실시간 데이터 요약]` — 매 요청 재계산
2. `[사전 분석 리포트]` — `insights.md` 고정 스냅샷
3. `[선택한 분석 주제]` — 사용자가 화면에서 고른 주제

**핵심 규칙 2개** (A7에서 넣은 것, 유지할 것):
- 현재 주제가 **대화 이력보다 우선**한다
- 답변 **첫 문장에서 어떤 주제 기준인지 밝힌다**

`ChatRequest.context`의 허용 키는 **`topic` 하나뿐**(`CONTEXT_KEYS`). 화이트리스트 검증이라 임의 키는 422가 난다.

## 항목별 요점

### A14 — 리포트 4블록 · **Wave 1 최우선**

R1이 CTA를 붙이려면 이 결정이 먼저 필요하다.

**정할 것**
1. **요청 방식** — 별도 엔드포인트(`POST /api/report`) vs `context`에 플래그 추가. 정하면 **R1에 알린다.**
2. **4블록을 강제하는 프롬프트** — `요약 / 핵심 수치 / 해석 / 한계`

**`한계` 블록은 생략 불가.** 이게 빠지면 경쟁 서비스와 차별점이 사라진다. 구조가 흔들리면 "리포트"가 아니라 그냥 긴 답변이 된다.

**어투**: `침착한 · 솔직한 · 정확한`. "유망하다", "추천한다" 같은 단정 어휘를 쓰지 않는다. **리포트에 없는 건 없다고 답한다**는 기존 규칙을 유지한다.

### A4 — 스트리밍 · **R1과 접점**

OpenAI SSE → 토큰 단위 출력. 마크다운(표·목록·굵게) 렌더.

**렌더는 화이트리스트 방식으로 XSS 차단을 유지한다.** 현재 프론트가 `textContent`만 쓰고 있는데, 마크다운을 도입하면 이 방어선이 약해진다. 임의 HTML을 넣지 않는 파서를 쓰거나 허용 태그를 명시한다.

> 스트리밍이 들어오면 대기 시간이 짧아지지만, **첫 토큰까지의 지연(콜드스타트 포함)은 그대로**라 A21은 여전히 필요하다.

### C4 — 로깅

요청마다 UUID, JSON 로그. `/api/chat`은 모델·프롬프트 토큰·완료 토큰·**추정 비용** 기록.

`usage`는 이미 `response.usage`에서 꺼내 응답에 싣고 있다. 로그에도 남기면 된다.

### C5 — 요약 캐시

`/api/data/summary`를 **매 채팅마다 재계산**하고 있다. 짧은 TTL(30초) 인메모리 캐시 + 데이터 변경 시 무효화.

**B2(전량 적재) 완료 후에는 사실상 필수다** — 수천~1만 건을 매 채팅마다 집계할 수 없다.

### B3 — 요약 필터

`/api/data/summary?district=&dong=&industry=&from=&to=`

**결정 ③(전량 적재)으로 필수성이 올라갔다** — 전량 데이터에서 전체 요약은 무의미하고, 필터가 있어야 대화가 성립한다. **B2 완료 후 착수.**

### C3 — 비용 방어

IP/세션 단위 분당 요청 제한 + 일일 누적 토큰 상한 → 429 + 안내. `CHAT_MAX_TOKENS`가 1차 방어선이고 이게 2차다.

### D3 — 시드 리셋

`POST /api/dev/reset` (토큰 보호). 리뷰어가 데모 데이터를 망가뜨려도 복구.

**B2 후에는 복구 대상이 커져 배치 삭제·재적재가 필요하다.**

## 절대 깨뜨리면 안 되는 것

### 1. 입력 검증 화이트리스트

Pydantic v2 검증을 약화시키지 않는다 — `Field(pattern=, max_length=, ge=, le=, allow_inf_nan=False)`, `field_validator`, `CONTEXT_KEYS`.

**회귀 확인**: `Inf` · `NaN` · 범위 초과 · 잘못된 날짜 · 빈 메시지가 전부 **422**를 내야 한다.

### 2. 비밀 정보

`.env` · `firebase-service-account.json`은 **gitignore 유지, 커밋 금지.** 값을 로그·문서·응답에 노출하지 않는다.

### 3. 쓰기 요청 폴링 금지

워밍업·상태 확인 목적으로 **mutating 요청을 반복 호출하지 않는다.** 과거 Firestore에 쓰레기 레코드가 쌓였다. 핑은 `GET /`만.

### 4. CORS

`ALLOWED_ORIGINS` 오리진 제한을 유지한다. 로컬 포트를 바꾸면 `.env`도 함께 맞춘다.

## 확인 방법

```bash
cd backend && uvicorn app.main:app --reload --port 8000
```

**한국어가 포함된 요청은 셸 인용이 깨진다.** JSON을 파일로 쓰고 `--data-binary @file.json`을 쓴다.

**배포본 확인**: Render는 설정된 브랜치만 배포한다. 고친 게 라이브에 없어 보이면 추측하지 말고 `openapi.json` 스키마를 비교한다.

**테스트 후 정리**: 기준 상태는 **conversations 0 / data 492**.
