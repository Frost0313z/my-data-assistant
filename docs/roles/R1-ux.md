## 왜 이 작업을 하는가

여정 6단계를 진단한 결과 **구멍이 두 개**다.

```
        Entry      Discovery    Evaluation    Decision     Action    Retention
골목상권  ●●●        ●●●          ●●●          ●●●         ●●●        ●●●
우리      ●○○        ●○○          ●●○          ●●●         ○○○        ●○○
          ↑A11·A12   ↑A9          ↑A10         (강점)      ↑A14       ↑A13
```

1. **Discovery** — 진입 질문이 "데이터 축"(8개 주제 버튼)이라 첫 사용자가 막힌다 → **A9**
2. **Action** — 여정에 종착점(산출물)이 없다. 주제 → 답변 → 끝 → **A14**

근거: [`../research/user-journey.md`](../research/user-journey.md)

## 항목별 요점

### A9 — 목적 기반 진입

주제 버튼 위에 **"무엇이 궁금하세요?"** 목적 칩 3개.

| 칩 | → 자동 선택 주제 |
|---|---|
| "어디가 뜨고 있나요?" | 성장·정체 |
| "내 업종은 어떤가요?" | 업종별 증감 |
| "여기 창업해도 될까요?" | 공급밀도 · 교체율 · 잔존율 |

클릭 시 **주제 자동 선택 + 질문 자동 전송**까지 한 번에.

> 벤치마크(서울시 골목상권)는 "창업 업종 있으세요? → 업종 선택 → 지역 선택" **3단계 마법사**다. **우리는 AI가 있으니 1클릭으로 압축한다** — 이게 차별점이다. 단계를 늘리면 후퇴다.

**수용 기준**: 처음 온 사용자가 칩 하나만 눌러 답변까지 도달한다.

### A10 — 주제별 제안 질문

지금 `chat.js`의 `SUGGESTIONS` 고정 3개를 **선택 주제 전용 질문**으로 교체.

예) 교체율 → "교체율 높은 동 TOP 5" / "교체율이 높으면 나쁜 건가?"

> 골목상권은 TOP 10 랭킹을 리스트로 렌더한다. **우리는 그걸 AI 답변으로 흡수한다** — 리스트는 정적이지만 AI는 "왜"까지 설명한다.

**수용 기준**: 주제를 바꾸면 제안 칩도 함께 바뀐다.

### A11 — 첫 방문 온보딩

모달로 막지 않고 **AI의 첫 인사말**로 서비스 정의·사용법을 전한다. `localStorage`로 재노출 억제.

문구는 [`../identity.md`](../identity.md)의 One-liner 기준: *"대전 82개 동 상권 흐름을 AI가 근거와 함께 설명합니다"*

### A14 — 주제 리포트 CTA · **R3 선행**

여정의 **종착점(산출물)** 을 만든다. 이게 서비스의 Primary Goal이다.

답변 뒤 `이 주제 전체 리포트 보기` 버튼 → AI가 고정 4블록으로 정리:
**요약 / 핵심 수치 / 해석 / 한계**

> **R3가 먼저 정할 것**: 요청 방식(별도 엔드포인트 vs `context` 플래그) + 4블록을 강제하는 시스템 프롬프트. **R3의 결정을 받고 시작한다.**

**`한계` 블록은 생략 불가** — 이게 빠지면 골목상권과 차별점이 사라진다.

### A21 — 대기 상태 타이머 · **문구는 R5 소유**

현재 `chat.js`는 `"생각하는 중..."` 정적 텍스트뿐이다. 콜드스타트면 **43초 동안 그대로**라 사용자가 멈춘 줄 안다.

| 경과 | 문구 |
|---|---|
| 0~5초 | `생각하는 중...` |
| 5초~ | `생각하는 중... (8초)` |
| 15초~ | `백엔드가 절전에서 깨어나는 중입니다. 최대 50초까지 걸릴 수 있어요. 요청은 계속 진행 중입니다. (18초)` |

**애니메이션 없이 숫자만 1초 간격 갱신.** 스피너로 "바쁜 척"하지 않는다 — 진행 상황을 사실로 알리는 게 이 브랜드의 대기 처리다.

> **문구 자체의 소유권은 R5다.** 현재 `cold` 에러 메시지가 "다시 시도해 주세요"인데 실제로는 자동 완료되므로 오안내이고, R5가 고친다. **같은 문구를 서로 다르게 고치지 않도록 R5와 맞춘다.** 이 역할은 **타이머 동작**을 담당한다.

### A19 — 증감 마크업 · **R2 선행**

수치 헤드라인의 증감 부분(`+2,800, +3.59%`)을 R2가 정의한 클래스로 감싼다.

**증감에 초록/빨강을 쓰지 않는다.** 매출이 없어 좋고 나쁨을 판단할 수 없다. R2가 `.trend-up` / `.trend-down` 색을 정의하면 마크업만 적용한다.

**문구도 규칙 대상**: 증감 옆에 "좋다/나쁘다/호조/부진" 어휘를 쓰지 않는다.

### A13 — 대화 제목 주제 태그

히스토리 제목을 `[공급 밀도] 이 주제 핵심만…` 형태로. 현재는 첫 메시지에서 파생돼 `이 주제 핵심만 한 줄로` 같은 제목이 중복 누적된다.

## 절대 깨뜨리면 안 되는 것

### 1. XSS 출력 이스케이프

**모든 문자열은 `createElement` + `textContent`로만 DOM에 넣는다.** `innerHTML` 보간 금지. 기존 코드가 전부 이 방식이니 따른다.

### 2. 주제 구분선 중복 방지

`chat.js`의 `lastNotifiedTopic` 가드를 유지한다. 같은 주제로 연속 호출될 때 구분선이 중복 출력되면 안 된다. 새 대화·불러오기 시 초기화도 유지.

### 3. 주제 단일 선택 · 재클릭 해제

`topics.js`의 라디오식 동작을 유지한다. 같은 버튼을 다시 누르면 해제되고 `window.screenContext = null`이 된다.

### 4. `screenContext` 계약

백엔드가 허용하는 키는 **`topic` 하나뿐**이다(`CONTEXT_KEYS`). 임의 키를 추가하면 422가 난다. 키를 늘리려면 **R3에 요청**한다.

## 확인 방법

```bash
# 프론트
cd frontend && python -m http.server 5500

# 백엔드 (같이 띄울 때)
cd backend && uvicorn app.main:app --reload --port 8000
```

> 로컬 포트를 바꾸면 백엔드 `.env`의 `ALLOWED_ORIGINS`도 맞춰야 한다. 안 맞으면 CORS 실패가 나는데, 이게 **"콜드스타트"로 잘못 분류되어** 엉뚱한 에러 메시지가 뜬다(실제 겪었던 혼선).

**테스트 후 정리**: 검증하며 만든 대화는 삭제한다. 기준 상태는 **conversations 0 / data 492**.
