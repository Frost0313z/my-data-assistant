# G. 온톨로지 — 질문이 화면을 세팅한다

> **상위**: [스펙 인덱스](README.md) · [문서 허브](../PORTFOLIO_SPEC.md) · **작성**: 2026-09-11 · **개정**: 2026-09-12
> 범례: **P0/P1/P2** 우선순위 · **S** ≤0.5일 / **M** 1~2일 / **L** 3일+
>
> **개정 사유** — 코드와 외부 대시보드에 대조하니 **검증 안 된 전제가 넷** 있었다. ① 파라미터 예시가 실재하지 않는 값이었다 ② 화면을 바꿔도 백엔드는 그 사실을 모른다 ③ 재사용하겠다던 함수들이 클로저 안에 닫혀 있었다 ④ G3의 설계로는 G7의 부정어 문항을 통과할 수 없었다. 공수는 **5~6일 → 7~9일**, G5는 둘로 쪼개 **G8**이 생겼다.

**참조** — 지명 사전의 **원본 데이터**는 이미 있다(`frontend/data/daejeon-map.json`의 `district`·`dong`·`dong_code`). 정규화 규칙도 이미 쓰이고 있다(`frontend/js/map.js`의 `initRegionSearch`). 이 그룹은 **그 데이터를 화면 → 채팅의 반대 방향으로 쓴다.**

⚠️ **다만 "이미 있으니 재사용하면 된다"가 아니다.** `map.js`는 `async` IIFE이고 밖으로 열린 것은 `window.setMapMetric` 하나뿐이다. `normalize`·`regions`·지역/시점 세팅은 전부 클로저 안에 있다. **재사용하려면 seam을 새로 뚫어야 하고, 그 비용이 G4의 공수에 들어 있다.**

---

## 왜

지금은 **화면 → 채팅** 한 방향이다. 고른 주제·지역·페르소나가 프롬프트에 실린다.

반대는 비어 있다. *"용문동은 가게가 얼마나 자주 바뀌어?"* 라고 물으면 **AI는 말로 답하고 지도는 딴 데를 보고 있다.** 눈으로 확인하려면 지표 셀렉트를 열어 `점포 교체율`을 고르고, 검색창에 `용문동`을 치고, 검색을 누른다 — **4동작**이고, 그마저 *교체율이라는 지표가 있다는 걸 알아야* 가능하다.

그리고 **콜드스타트 43초가 통째로 버려진다.** 그동안 화면이 이미 답을 보여주고 있으면 체감이 완전히 달라진다.

---

## 이 그룹의 범위

**하는 것** — 질문에서 지표·지역·시점·무대를 알아내 화면을 맞춘다. **못 답하는 질문이면 화면을 바꾸지 않는다.**

**무대는 둘이다** — 지도(행정동 코로플레스 7지표)와 대시보드 5탭(임베드). 둘은 축도 입도도 다르고, **같은 라벨이 다른 개념을 가리키는 곳도 있다**(`점포 교체율`). 사전은 둘 다 알아야 한다.

### AI의 답은 바꾸지 않는다 — 범위 밖이다

화면만 맞춘다. **백엔드로 가는 컨텍스트에는 손대지 않는다.**

`CONTEXT_KEYS`는 `{topic, mode, persona, regionType}`뿐이라 `metric`·`district`·`dong`·`period`를 애초에 받지 않는다. 넓히지 않는 이유는 **필요가 없어서다** — 의도가 잡히는 질문은 *"용문동은 가게가 얼마나 자주 바뀌어?"* 처럼 **그 단어들을 질문 자체가 이미 들고 있다.** 백엔드는 질문 원문을 그대로 받으므로 컨텍스트 키는 같은 말의 중복이다.

**남는 구멍은 후속 질문 하나다** — *"그럼 옆 동네는?"* 은 화면에만 있는 상태를 가리킨다. 이건 **이 그룹이 만든 구멍이 아니라 지금도 있는 한계**다. 나중에 메우려면 `CONTEXT_KEYS`에 키를 더하고 `CONTEXT_ENUMS`처럼 **값까지 화이트리스트**로 막으면 된다(+S). 지금은 하지 않는다.

> 그래서 **G3의 "되먹임"은 이 키들에서는 일어나지 않는다.** 실제로 되먹임이 생기는 경로는 딱 하나, **G5가 탭을 바꾸면서 `screenContext.topic`을 다시 쓰는 것**이다 — G4의 캡처 순서 규칙이 그걸 막는다.

**안 하는 것**
- OWL·추론기·트리플스토어. 이 규모에서 과하다. **통제 어휘 + 제약표**까지다.
- 다만 **JSON-LD `@context`는 얹는다** — 런타임 비용이 0이라 "안 하는 것"에 둘 이유가 없다. 근거와 정확한 형태는 [부록 A](#부록-a-json-ld--왜-이것만-얹는가).
- 화면 세팅에 LLM을 부르지 않는다(G3 근거 참조).
- 질문을 대신 보내지 않는다. 화면만 맞추고 답은 사용자의 질문 그대로 받는다.
- 사용자가 맞춰 둔 것을 말하지 않은 부분까지 바꾸지 않는다.

## 전제 — 임베드 대시보드는 우리 것이 아니다

탭 5개는 **외부 GitHub Pages**를 iframe으로 띄운 것이다(`config.js`의 `DASHBOARD_URL` → `frost0313z.github.io`). 받는 파라미터는 **그쪽이 정한 계약**이고 우리가 못 바꾼다. 2026-09-11 기준 원문에서 확인한 전부:

```
?only=<data-section>[,…]        stats·map·heatmap·growth·turnover·series·bar·table
?metric=density|hhi|survival    ← 지도 7지표가 아니라 3종뿐이다
?category=<업종>
?bar=district|category|dong
?sort=change|growth|score       ← count·dir 같은 건 없다
?series=city|district|category|dong
```

⚠️ **틀린 값은 조용히 무시된다.** 적용 코드가 `el.value = val; if (el.value === val) dispatch(...)` 라서, **없는 값을 넣으면 에러도 신호도 없이 기본값으로 열린다.** 사용자는 요청대로 맞춰졌다고 믿는다 — 이 그룹이 없애려는 *"답한 척"* 과 같은 실패다.

**그래서 파라미터는 위 목록의 닫힌 enum에서만 고른다.** 질문 문자열에서 뽑은 값을 그대로 URL에 붙이지 않는다. 사전(G1)의 `accepts`가 이 계약을 그대로 베껴 적고, CI(G7)가 사전의 값이 이 목록 밖으로 나가면 깬다.

**바깥이 바뀌면 조용히 깨진다.** iframe은 교차 출처라 적용 여부를 읽어올 수 없다 — 성공을 확인할 방법이 없다. 이것이 G8을 P2로 내려놓는 이유다.

| **G4** | 화면 적용 · 알림 · 되돌리기 | P1 | **M** | 의도를 셀렉트·지도에 적용한다. `initRegionSearch`가 하는 일(자치구+동 세팅 후 지도 맞춤)과 **같은 일을 하되, 먼저 꺼내 써야 한다.**<br><br>**S가 아니라 M인 이유 — 여기에 숨은 일이 넷 있다.**<br>① **seam 신설**: `map.js`는 `async` IIFE다. 열린 건 `window.setMapMetric` 하나뿐이고 지역·시점 세팅은 클로저 안이다. `applyRegion`·`applyPeriod`를 같은 방식으로 노출한다.<br>② **준비 전 큐**: `window.setMapMetric`은 `await fetch` **뒤에** 정의된다. *"콜드스타트 43초 동안 화면이 이미 답"* 이 이 그룹의 핵심 주장인데 **그 구간이 바로 지도가 아직 없는 때다.** 이미 있는 `window.pendingMapMetric` 패턴을 지역·시점으로 넓힌다.<br>③ **폴백 분기**: 지도 로드가 실패하면 대체 화면이 뜬다. 그때 *"지도를 맞췄습니다"* 라고 말하지 않는다.<br>④ **되돌리기 스냅샷**: 적용 직전 상태(지표·시점·자치구·동·무대)를 한 벌 떠 두고 한 번에 복원한다.<br><br>**전송 컨텍스트를 먼저 캡처한다.** `chat.js`는 보낼 때 `window.screenContext`를 읽는데(`sendMessage`), 의도 적용이 그보다 먼저 돌면 **사용자가 고르지 않은 주제가 프롬프트에 실린다.** 순서를 못 박는다 — **컨텍스트 캡처 → 전송 시작 → 의도 적용.** 이 영역은 전례가 있다(`chat.js`의 *"주제를 요청을 보낸 시점의 것으로 받는다"*).<br><br>**말한 것만 바꾼다.** *"대덕구는?"* 이면 자치구만 갈고 지표·시점은 그대로 둔다. 사용자가 맞춰 둔 화면을 조용히 리셋하는 것이 이 기능의 최악의 실패다.<br><br>**바뀐 것을 알린다.** A29의 `.topic-divider` 자리를 쓴다 — *지도를 **교체율 · 서구 용문동**으로 맞췄습니다 · 되돌리기*. A30에서 배운 것이 이거다: 화면이 말없이 움직이면 혼란스럽다.<br><br>**되돌리기는 필수다.** 잘못 잡았을 때 한 번에 이전 상태로. 패턴 매칭이라 틀릴 수 있고, 틀렸을 때 빠져나갈 길이 없으면 안 쓰느니만 못하다.<br><br>접근성: 셀렉트를 코드로 바꿀 때 `change` 이벤트를 발생시키고, 변경 사실을 `map-search-feedback`(이미 `role="status"`)로 읽어 준다.<br><br>⚠️ **알림은 `textContent`로만 만든다.** 여기가 사용자 입력이 화면으로 되돌아 나오는 **새 지점**이다. 기존 `innerHTML` 금지 검사는 `markdown.js` 원문만 보므로(`check_markdown.js`), **새 파일을 그 검사 대상에 넣는다** | 지정하지 않은 셀렉트는 **값이 유지된다**. 알림 한 줄이 뜨고 되돌리기가 **이전 상태를 정확히 복원**한다. 스크린리더가 변경을 읽는다. 지도가 아직 없을 때 물어도 **뜬 뒤에 반영된다**. 새 파일이 `innerHTML` 검사를 통과한다 |
| **G5** | 무대 선택 — 입도로 가른다 | **P1** | M | 지도가 답할 수 없는 질문이 있다. *"서구랑 동구 중 어디가 더 안정적이야?"* — 지도는 한 번에 한 곳만 고른다. 지금은 **사용자가 탭 5개 중 무엇을 봐야 하는지 스스로 알아내야 한다.**<br><br>**① 같은 단어, 다른 무대.** `grain`으로 가른다 — *"용문동 교체율은?"* 은 한 지역의 값이라 **지도**, *"교체율 높은 데가 어디야?"* 는 분포라 **산점도 탭**. 라벨이 같아도 다른 개념이다(G1의 동명이개념).<br><br>**② 입도가 안 맞으면 보내지 않는다.** *"용문동 업종 구성은?"* — 히트맵은 `district×industry` 입도라 행정동 답을 못 낸다. **지도 업종 점**으로 보내거나, 그것도 안 되면 못 한다고 말한다. 모르면 **엉뚱한 탭을 열어 놓고 답한 척**하게 된다 — G2와 같은 실패다. **P2에서 P1으로 올린 이유가 이것이다.**<br><br>⚠️ **`topics.js`의 `select()`를 그대로 부르면 안 된다.** 그 함수는 **토글**이라(`activeId = id === activeId ? null : id`) 이미 열린 탭의 id로 부르면 **닫히고 지도로 돌아간다.** 게다가 `notifyTopicChange`로 **채팅에 주제 구분선을 남긴다** — G4의 되돌리기까지 하면 구분선이 두 개 쌓인다. **토글 없고 구분선을 억제할 수 있는 전용 진입점**을 연다 | 비교형 질문에서 적절한 탭이 열린다. 단일 지역 질문은 지도에 남는다. **입도가 안 맞는 질문은 무대를 바꾸지 않고 이유를 말한다.** 이미 열린 탭을 다시 지목해도 **닫히지 않는다.** 자동 전환에는 구분선이 **한 번만** 남는다 |
| **G6** | 불가능한 조합 차단 | P2 | S | 제약을 사전에 적고 지킨다.<br>① `category ⟂ period` — 업종 점은 최신 1시점뿐이다. 지금은 작은 안내문으로만 알리는데 **읽는 사람이 거의 없다.** 시점을 바꾸지 않고 왜 안 되는지 답한다.<br>② ~~`periods: all` 지표의 시점 선택을 맞춘다~~ — **이미 돼 있다.** `applyMetric`이 `period.disabled = !!spec().allPeriods`로 막는다. 사전에 사실로만 적고 코드는 건드리지 않는다.<br>③ `density`는 인구 분모가 필요하다.<br><br>②가 빠져 **S의 아래쪽 끝**이 됐다 | 불가능한 조합을 요청하면 **화면이 어긋난 상태로 가지 않고** 이유를 한 줄로 답한다 |
| **G7** | 검증 — 질문→기대 의도 표 | P1 | S | `resolveIntent`가 순수 함수라 표로 테스트된다. 최소 30문항: 정상 매칭 · **거절**(매출·유동인구) · 모호(빈 객체) · 부분 매칭(지명만/지표만) · **부정어**(*"매출 말고 교체율"* → turnover) · **활용형**(*"망했"·"망해요"*) · **입도 불일치**(행정동 업종 구성 → 무대 유지).<br><br>**방식은 이미 증명돼 있다.** `check_markdown.js`가 `global.window = {}`를 세워 두고 `require`로 브라우저 없이 돈다. `resolveIntent`를 같은 `(function (window) { … })(window)` 꼴로 두고 **DOM을 만지지 않으면** 그대로 붙는다 — 순수 함수로 잡은 값이 여기서 나온다.<br><br>사전의 파라미터 값이 「전제」의 계약 밖으로 나가면 **깬다**(조용히 무시되는 URL을 미리 잡는 유일한 방법이다).<br><br>CI의 `check_markdown.js`·`check_map_data.js` 옆에 `check_ontology.js`로 붙인다. **커버리지를 숫자로 남긴다** | CI에서 돈다. 사전을 고쳐 기대가 깨지면 **빌드가 깨진다**. 계약 밖 파라미터 값이 있으면 깨진다. 커버리지 숫자가 출력된다 |
| **G8** | 탭 파라미터 세팅 | P2 | S | *"증감률 순으로 자치구 보여줘"* → `only=bar&bar=district&sort=growth`. 탭만 열고 정렬을 기본값으로 두면 사용자가 다시 손봐야 한다.<br><br>**G5에서 떼어 냈다.** 무대를 고르는 것은 정확성(P1)이지만 정렬까지 맞추는 것은 **편의**이고, 무엇보다 **우리가 통제하지 못하는 외부 계약에 묶여 있다**(「전제」 참조). 값이 틀려도 조용히 무시되고, 교차 출처라 **적용됐는지 읽어올 수도 없다** — 확인할 수 없는 기능을 정확성 항목에 둘 수 없다.<br><br>**G5보다 먼저 하지 않는다.** 무대가 틀린 채로 정렬만 맞추는 것은 의미가 없다 | 계약 안의 값으로만 URL을 만든다. **질문 문자열이 URL에 그대로 실리지 않는다.** 계약 밖 값은 G7이 CI에서 잡는다 |

## 예상 효과 — 그리고 한계

| 항목 | 지금 | G 적용 후 |
|---|---|---|
| 수동 동작(매칭되는 질문) | 4회 | **0회** |
| 화면 반영 시점 | 사용자가 직접 할 때 | **질문 누른 즉시**(0.1초 이내) |
| 콜드스타트 43초 | 버려짐 | **화면은 이미 답** |
| "어느 탭을 봐야 하나" | 사용자 몫 | 시스템 몫(G5) |
| 입도 안 맞는 질문 | 엉뚱한 탭을 열고 답한 척 | **무대를 안 바꾸고 이유를 말함**(G5) |
| 거절의 일관성 | 말로만 | **말 + 화면**(G2) |
| AI 답변의 내용 | — | **그대로**(범위 밖) |
| 추가 토큰 비용 | — | **0** |

**커버리지는 50%대로 본다.** 처음에 60~70%로 잡았다가 내렸다 — **한국어 활용형** 때문이다. 어간 분석기 없이 별칭을 나열하는 방식이라 *"망했"·"접었"·"버티나"* 같은 변형을 다 적어야 잡힌다. 여기에 *"작년보다 나아진 동네"* 처럼 애초에 사전으로 안 잡히는 질문이 더해진다.

**추정을 낮추는 것이 기능을 낮추는 것은 아니다.** 아래 이유로 못 잡힌 질문의 비용이 0이기 때문에, 커버리지는 "얼마나 이득인가"이지 "얼마나 위험한가"가 아니다.

**안 잡히면 지금과 똑같다.** 화면이 안 바뀔 뿐 후퇴가 없다 — 이것이 LLM에 시키는 것과의 결정적 차이다. LLM은 **틀리게** 바꿀 수 있다.

> **이건 이해가 아니라 패턴 매칭이다.** 그래서 G4의 *"말한 것만 바꾼다"* 와 *"되돌리기"* 가 선택이 아니라 전제다.

## 순서

**G2 → G1 → G3 → G4 → G5 → G7 → (G6) → (G8)**

거절부터 만든다. **다만 G2 시점에 증명되는 것은 칩과 문구까지다** — 화면을 바꾸는 코드가 아직 없으니 *"화면이 안 움직인다"* 는 공짜로 참이고, 그래서 반증이 안 된다. **그 기준은 G4 뒤에 다시 잰다.** 이건 G2를 뒤로 미룰 이유가 아니라 **언제 무엇이 증명되는지 헷갈리지 않기 위한 구분**이다.

**G5가 뒤에서 앞으로 올라왔다.** 처음에는 "비교 질문을 적절한 탭으로 보낸다"는 편의 기능으로 봤는데, 다시 보니 **입도가 안 맞는 무대로 보내는 것이 G2와 같은 종류의 실패**였다 — 답할 수 없는 것을 답한 척하는 것. 편의가 아니라 정확성 항목이다.

**G8은 G5에서 떨어져 나와 맨 뒤로 갔다.** 같은 이유의 반대편이다 — 무대를 고르는 것은 정확성이지만 **정렬까지 맞추는 것은 편의**이고, 그마저 **바깥 저장소의 계약**에 묶여 있어 우리가 확인할 수 없다.

G6는 여전히 뒤다. 제약 위반은 드물고, 어긋나도 화면이 이상해질 뿐 틀린 답을 주지는 않는다.

### 공수 합계

| 항목 | 크기 | 합 |
|---|---|---|
| G1 · G3 · G4 · G5 | M × 4 | 4~8일 |
| G2 · G6 · G7 · G8 | S × 4 | ~2일 |

**7~9일**로 본다. 처음 추정(5~6일)보다 늘었고, **늘어난 대부분이 G4의 seam·큐·되돌리기**다 — "이미 있으니 재사용하면 된다"고 적었던 부분이 실제로는 닫혀 있었다.

## 부록 A. JSON-LD — 왜 이것만 얹는가

### 한 줄

**JSON-LD는 그냥 JSON이다.** `@context` 키 하나가 더 있고, 그 키가 *"이 파일의 `label`은 schema.org의 `name`을 뜻한다"* 라고 적어 둔다. 그 선언 덕분에 같은 파일이 **유효한 RDF**가 된다 — 파일을 바꾸지 않고, 파서를 바꾸지 않고.

```js
// @context가 있든 없든 이 줄은 똑같이 돈다
const dict = await (await fetch("/data/ontology.json")).json();
dict.metrics.turnover.aliases;   // ["교체율", "망하", ...]
```

`resolveIntent()`는 `@context`를 **한 번도 읽지 않는다.** 런타임 비용이 0인 이유가 이것이고, "안 하는 것"에서 이것만 빼낸 이유도 이것이다.

### 키워드는 셋이면 된다

| 키워드 | 뜻 | 우리 쓰임 |
|---|---|---|
| `@context` | 지역 키 → 전역 어휘 매핑 | 파일 맨 위 한 블록 |
| `@id` | 이 노드의 이름(식별자) | `#turnover`, `#dong-30170550` |
| `@type` | 이 노드가 무엇인가 | `PropertyValue`, `AdministrativeArea` |

`@graph`(노드 목록), `@language`(문자열 언어) 정도가 더 있고, 나머지는 우리 규모에서 안 쓴다.

### 우리 파일에 얹으면

```json
{
  "@context": {
    "@vocab": "https://schema.org/",
    "@language": "ko",
    "label":   "name",
    "aliases": "alternateName",
    "unit":    "unitText",
    "metrics": "variableMeasured",

    "answers": null,
    "cannot":  null,
    "periods": null,
    "grain":   null,
    "stages":  null
  },

  "@type": "Dataset",
  "name": "대전 상권 온톨로지 사전",

  "metrics": [
    {
      "@id": "#turnover",
      "@type": "PropertyValue",
      "label": "점포 교체율",
      "unit": "%",
      "aliases": ["교체율", "망하", "폐업", "자주 바뀌", "버티", "오래 가"],
      "periods": "all",
      "grain": "dong",
      "answers": "한 동네에서 가게가 얼마나 자주 바뀌는가",
      "cannot": ["매출", "유동인구", "특정 점포의 생존 여부"]
    }
  ]
}
```

**`null`이 이 블록에서 제일 중요한 줄이다.** JSON-LD에서 용어를 `null`로 두면 *"이 키는 RDF가 아니다"* 라는 **명시적 선언**이 되어 확장 단계에서 빠진다.

`answers`·`cannot`·`grain`은 **이 프로젝트에서만 뜻이 있는 말**이다. 여기에 그럴듯한 IRI를 지어 붙이면(`https://example.com/ns#answers`) 열어도 아무것도 없는 주소가 생기고, 그건 **없느니만 못하다** — 의미가 있는 척하는 장식이다. `null`은 "표준 어휘로는 이걸 못 적는다"를 정직하게 적는 방법이다.

> **규칙: 이미 있는 어휘를 쓰거나, 아니면 `@context`에 넣지 않는다.** IRI를 새로 만드는 순간 그 주소를 유지할 책임이 생긴다.

### 지명에서 실제로 값을 한다

경계 데이터의 용문동 하나가 **식별자를 이미 셋** 들고 있다:

```json
{ "dong_code": "30170550", "source_adm_cd": "25030560", "source_adm_cd2": "3017055000" }
```

같은 동네에 코드 체계가 셋이라는 뜻이고, 이걸 구조 없이 두면 *"30170550이 뭐였더라"* 를 매번 코드에서 되짚어야 한다. JSON-LD에는 정확히 이걸 위한 관용구가 있다:

```json
{
  "@id": "#dong-30170550",
  "@type": "AdministrativeArea",
  "name": "용문동",
  "containedInPlace": { "@id": "#gu-seogu", "name": "서구" },
  "identifier": [
    { "@type": "PropertyValue", "propertyID": "dong_code",      "value": "30170550" },
    { "@type": "PropertyValue", "propertyID": "source_adm_cd",  "value": "25030560" }
  ]
}
```

이건 온톨로지 취향의 문제가 아니라 **이미 있는 혼란에 이름을 붙이는 것**이다.

### 얻는 것 셋

**① 나중에 트리플스토어가 필요해져도 이사 비용이 없다.** RDF 툴은 전부 JSON-LD를 직접 읽는다. 지금 0의 비용으로 선택지를 사 두고, 안 쓰면 안 쓰는 것이다.

**② `index.html`의 `Dataset` 블록 — 이건 진짜 쓰인다.** Google Dataset Search가 데이터셋을 수집하는 방법이 문자 그대로 이것이다.

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org/",
  "@type": "Dataset",
  "name": "대전 행정동 상권 지표 (82개 동, 6시점)",
  "description": "행정동별 공급 밀도·점포 교체율·잔존율·업종 집중도. 매출과 유동인구는 포함하지 않는다.",
  "spatialCoverage": { "@type": "Place", "name": "대전광역시" },
  "temporalCoverage": "2023-06/2025-12",
  "license": "https://opendatacommons.org/licenses/odbl/",
  "creator": { "@type": "Person", "name": "..." }
}
</script>
```

`description`에 **한계를 적는 것**을 눈여겨볼 것 — G2가 화면에서 하는 말을 메타데이터에서도 한다. 공모전 심사자가 열어 보는 첫 화면에서 이 블록은 "데이터 출처와 한계를 아는 사람"이라는 신호다.

⚠️ CSP: 인라인 `<script>`다. `application/ld+json`은 **실행되지 않는 데이터 블록**이라 `script-src`가 막지 않지만, 넣은 뒤 콘솔에서 실제로 확인한다 — 예전에 테마 인라인 스크립트로 한 번 데었다.

**③ `sameAs`로 바깥과 잇는다.** 업종 분류 같은 것을 나중에 표준 코드에 붙일 자리가 생긴다. 지금은 안 한다.

### 못 하는 것 — 여기가 선이다

`@context`는 **뜻을 적을 뿐 검사하지 않는다.**

- 단일 시점 지표에 `periods: "all"` 을 잘못 적어도 **아무도 안 잡는다** → 그건 G6의 제약표와 G7의 CI가 한다
- `@context`만으로는 *"고밀도동"* 같은 새 사실이 안 나온다 → 그게 추론기이고, 우리는 `value >= 100` 비교 한 줄이라 필요 없다
- 질의(SPARQL)도 안 된다 → `resolveIntent()`가 하는 일이다

**즉 JSON-LD는 "표현"만 준다. 검증·추론·질의는 여전히 우리 코드와 CI가 한다.** 그래서 공짜고, 그래서 이것만 얹는다.

### 공수

`@context` 블록 + `Dataset` 블록 = **S 이하**, G1에 딸려 간다. 별도 항목으로 세우지 않는다.
