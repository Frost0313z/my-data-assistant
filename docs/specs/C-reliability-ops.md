## C. 신뢰성 · 운영

| ID | 항목 | P | 공수 | 내용 | 수용 기준 |
|---|---|---|---|---|---|
| **C1** | pytest 통합 테스트 스위트 | P0 | M | `test_models.py` 단일 assert 파일 → `pytest` 기반. 라우터별 통합 테스트(`TestClient`), Firestore/OpenAI는 페이크/모킹 | `pytest` 실행 시 데이터 CRUD·요약·채팅 핵심 경로가 커버되고 전부 통과 |
| **C2** | GitHub Actions CI | P0 | S | 푸시·PR마다 `pytest` + 프론트 `node build.js` 스모크. 통과 시에만 배포 | main 배지가 초록, 실패 시 배포 차단 |
| **C3** | 채팅 rate limit + 일일 토큰 상한 | P1 | M | IP/세션 단위 분당 요청 제한, 일일 누적 토큰 상한 도달 시 429 + 안내. 비용 폭주 방지 | 짧은 시간 다수 요청 시 429, 상한 도달 시 사용자에게 명확한 메시지 |
| **C4** | 구조적 로깅 + 요청 ID + 토큰/비용 로그 | P1 | S | 요청마다 UUID, JSON 로그. `/api/chat`은 모델·프롬프트 토큰·완료 토큰·추정 비용 기록 | Render 로그에서 한 요청을 ID로 추적, 채팅 1건당 비용이 보인다 |
| **C5** | 요약 결과 캐시 | P1 | S | `/api/data/summary`를 매 채팅마다 재계산 중 → 짧은 TTL(예: 30초) 인메모리 캐시, 데이터 변경 시 무효화. **B2(전량 적재) 완료 후 사실상 필수** | 연속 채팅에서 Firestore 조회가 매번 발생하지 않는다 |
| **C6** | 콜드스타트 핑 + 로딩 안내 | P1 | S | 외부 크론(cron-job.org 등)으로 10분마다 `/` 핑. 프론트는 최초 요청 시 "백엔드 깨우는 중(최대 50초)" 안내 유지 | 데모 시 첫 응답 지연이 사용자에게 설명되고, 핑으로 스핀다운 빈도가 준다 |
| **C7** | 에러 트래킹 | P2 | S | Sentry 무료 티어 연동(백엔드·프론트). 미처리 예외 자동 수집 | 의도적으로 에러를 내면 Sentry에 이벤트가 잡힌다 |

> **C6 참고 — 콜드스타트 실측**: Render 무료 티어는 15분 유휴 후 스핀다운되고, 이후 첫 요청을 **붙잡아둔 채 완료시킨다**(실측 43초). `fetch`에 기본 타임아웃이 없어 **자동으로 완료된다** — 사용자가 재시도할 필요는 없다. 다만 그 사이 UI 피드백이 없는 것이 문제다.
>
> **금지**: 워밍업·상태 확인 목적으로 **쓰기(mutating) 요청을 폴링하지 않는다.** 과거 Firestore에 쓰레기 레코드가 쌓인 적이 있다. 핑은 `GET /`만 쓴다.

## 운영 제약

| 제약 | 내용 |
|---|---|
| 비밀 정보 | `firebase-service-account.json`, `.env`는 **gitignore 유지, 절대 커밋 금지.** 값을 로그·문서·대화에 노출하지 않는다 |
| CORS | `ALLOWED_ORIGINS`로 오리진 제한 유지. 로컬 포트를 바꾸면 `.env`도 함께 맞춘다 |
| 비용 | 출력 상한(`CHAT_MAX_TOKENS`)과 입력 억제(캐시 프리픽스·이력 상한)가 1차 방어선 → 아래 §토큰·비용. C3이 2차 |
| 배포 | Render는 **설정된 브랜치만** 배포한다. 브랜치 설정과 실제 배포본이 어긋나면 `openapi.json` 스키마로 확인하는 것이 가장 확실하다 |

## 토큰·비용 (구현됨, 2026-09-09)

| | 값 | 이유 |
|---|---|---|
| `CHAT_MAX_TOKENS` | 900 | 500에서는 지표를 여럿 묻는 질문이 문장 중간에 끊겼다(실측). 900에서 같은 질문의 답이 470토큰으로 완결됐다 — 상한은 잘림만 없애고 답변을 늘리지 않는다 |
| `REPORT_MAX_TOKENS` | 1200 | 4블록 구조를 채워야 한다. [한계] 블록이 잘리면 안 된다 |
| `HISTORY_MAX_MESSAGES` | 8 | 이력을 매 요청 통째로 다시 올린다. 상한이 없으면 입력이 대화 길이에 비례해 늘어난다 |
| 프롬프트 블록 순서 | 고정 → 가변 | OpenAI 자동 캐싱은 **앞에서부터 같은 구간**만 1,024토큰 이상일 때 재사용한다. 고정 프리픽스 2,432자(전체의 95%), 실측 `cached_tokens=1024` |

**셋 다 환경변수로 덮을 수 있다.** 배포에서 값만 바꿔 대응한다.

주의: 가변 블록(요약·주제·페르소나)이 하나라도 앞으로 올라가면 그 뒤 전체가
캐시에서 빠지는데 **응답은 멀쩡해서 아무도 모른다.** `backend/test_models.py`가
프리픽스 길이를 검사한다.
