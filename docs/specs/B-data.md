## 대시보드 원본 데이터 — 자산 인벤토리

`frontend/scripts/build_map_data.py`가 분석 저장소 대시보드에서 데이터를 추출한다(출처 URL + SHA256 기록). **대시보드가 단일 소스이고 우리 파일은 파생물이다** — 원본이 바뀌면 스크립트를 다시 돌린다. 이중 관리가 아니다.

대시보드 `const data` 안에 든 것 전부와, 우리가 쓰는지 여부다.

| 키 | 내용 | 사용 | 용량 |
|---|---|---|---|
| `dongBoundaries` | 82개 행정동 경계 (vuski/admdongkor, MIT) | ✅ A22 | 현재 파일의 대부분 |
| `boundaries` | 5개 자치구 경계 (OSM/Nominatim, **ODbL**) | ✅ A22 | 포함 |
| `dongMetrics` | 동별 `density`·`hhi`·`survival` × 6시점 | ⚠️ **density만** — 나머지 둘은 **이미 파일에 들어 있는데 화면이 안 쓴다** | 포함 |
| **`mapPoints`** | **실제 위경도 + 업종 + 점포 수** (시점당 ~2,300점, 10업종, count 합 80,704) | ❌ 미사용 → **A25** | 1시점 203KB / 전체 1.2MB |
| **`dongs`** | 동별 **절대 업소 수** 시계열 | ❌ 미사용 → **A23** | 10KB |
| **`dongTurnover`** | 동별 폐업(`left`)·개업(`entered`) 5구간 | ❌ 미사용 → **A23·A26** | 6KB |
| `combinations` | 자치구 × 업종 (50조합) | ❌ 미사용 — 구 단위 5개뿐이라 지도 가치 낮음 | 7KB |
| `categories`·`city` | 시 전체 업종·총계 시계열 | ❌ 지도용 아님 | — |

현재 `daejeon-map.json`은 **365KB**다.

- `dongs` + `dongTurnover` = **+16KB**. 사실상 공짜.
- `mapPoints` 최신 1시점 = **+203KB** (좌표 4자리로 줄여도 198KB, 효과 미미).
- `mapPoints` 전 시점 = **+1.2MB** → 합 1.5MB. **`roadmap.md` 리스크 표에 "대시보드 1.8MB 단일 파일"이 이미 올라 있다. 같은 실수를 반복하지 않는다.**

### 임베드 패널 캐시

패널은 `?only=<섹션>` 쿼리로 같은 1.78MB 파일을 부른다. 응답 헤더가 `Cache-Control: max-age=600`이라 **10분 안에 다시 열면 네트워크 요청이 없다.** 다만 브라우저 캐시 키는 쿼리를 포함하므로 **서로 다른 섹션은 각각 첫 로드 비용을 낸다.** 8개를 다 보면 최악 14MB, 5개면 8.9MB다. → A27이 패널 수를 5개로 줄이는 근거.

## 주의

- **B2 재실행 안전성이 수용 기준이다.** 대량 적재는 중간 실패가 잦으므로 upsert가 아니면 중복이 쌓인다.
- **B2 완료 후 D3(시드 리셋)의 성격이 바뀐다** — 복구 대상이 커져 배치 삭제·재적재가 필요하다. → [`C-reliability-ops.md`](C-reliability-ops.md)
- **B2 완료 후 C5(요약 캐시)가 사실상 필수가 된다** — 매 채팅마다 전량 집계는 비현실적이다.
- 수치를 바꾸면 `frontend/js/topics-data.js`와 `backend/app/seed/insights.md`가 **같은 출처를 써야 한다.** 한쪽만 고치지 않는다.
