# ADR 0005 — 키와 오리진을 어떻게 다루는가

**상태** 유효 · **날짜** 2026-09 (사후 기록)

## 맥락

OpenAI 키와 Firebase 서비스 계정 키가 있다. 프론트는 정적 호스팅(Vercel), 백엔드는 Render다.

## 결정

- **키는 백엔드에만 둔다.** 프론트는 OpenAI를 직접 부르지 않는다.
- `.env`·`firebase-service-account.json`은 gitignore 유지, **값을 문서·로그·대화에 노출하지 않는다.**
- Firebase 키는 파일 경로 또는 JSON 문자열 둘 다 받는다. 배포 환경에는 파일을 못 두기 때문이다.
- CORS는 `ALLOWED_ORIGINS` 환경변수로 좁힌다.

## 트레이드오프 — CORS 기본값

기본값이 `*`다. 좁히자는 지적이 있었지만 **그대로 뒀다.**

`ALLOWED_ORIGINS`가 빠진 배포에서 기본값이 좁으면 프론트가 그냥 죽는다. 원인도 안 보인다. 대신 **조용하지 않게** 만들었다 — 시작 로그가 실효 설정을 남기고, 와일드카드면 `cors.wildcard` 경고를 낸다.

진짜 방어는 오리진이 아니라 **남용 자체**에 걸었다(C3: 분당 요청 + 일일 토큰 상한). 오리진 제한은 브라우저만 지키고 `curl`은 안 지킨다.

## 파괴적인 엔드포인트

`POST /api/dev/reset`은 데이터를 지운다. `DEV_RESET_TOKEN`이 없으면 **503이 아니라 404**를 낸다. 503으로 "여기 있는데 꺼져 있다"고 알려 주면 토큰을 설정한 순간 두드릴 곳을 미리 광고하는 셈이다.

## 에러 트래킹의 개인정보

Sentry는 `send_default_pii=False` + `before_send` 필터로 **사용자의 질문과 답변이 이벤트에 실리지 않게** 두 겹으로 막는다. 이 서비스가 다루는 건 사람이 어디에 창업할지 묻는 말이다.
