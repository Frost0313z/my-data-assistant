## 지도 중심 전환 (2026-09-09)

| # | 질문 | 결정 | 스펙 영향 |
|---|---|---|---|
| **⑦** | 첫 화면의 주역 | **대전 지도** — 공급 밀도를 2D/3D로 로컬 렌더 | **A22 신설**. ①을 부분 뒤집음 |

**①의 "이식(재구현)은 비범위"를 대전 지도에 한해 푼다.** 사용자 지시:

> 유저가 경험해야 하는 부분은 맵임. 상권분석에서 중요한 것은 지도야. 공급 밀도 부분 지도가
> 2D 형태도 제공되어 있는데 **대전 지역에 한해서만 2D와 3D를 병행**하여 입체감 있게 나타났으면 좋겠어.

**①을 통째로 뒤집는 게 아니다.** 나머지 7개 주제는 그대로 iframe 임베드를 쓰고(`renderEmbed` 유지),
공급 밀도만 로컬 SVG로 재구현한다. 이유는 세 가지다.

- **상권 분석의 진입점은 지도다.** 임베드는 크로스오리진이라 클릭을 받아 채팅 컨텍스트로 넘길 수 없다.
- **3D는 임베드로 불가능하다.** 원본 대시보드에 없는 표현이라 우리가 그릴 수밖에 없다.
- **범위를 대전으로 못 박았다.** 다른 지역까지 열면 "이중 관리하지 않는다"는 ①의 이득이 실제로 사라진다.

대신 **원본 지도 링크를 화면에 유지**해 검증 경로(Secondary Goal)를 끊지 않는다.

레이아웃도 함께 바뀐다 — 3분할에서 **지도 중심 2분할**로. 사이드바(요약·기록·데이터)와
주제 영역은 접고, 채팅은 폭을 줄인다. 사용자가 지적한 "답답함"이 근거다.

> **경위**: 이 작업은 사용자가 코덱스에 직접 지시해 진행됐고 조율자를 거치지 않았다.
> 그래서 스펙 ID 없이 코드가 먼저 들어왔다. 기록을 나중에 맞춘 사례로 남긴다.

## 설계 판단 (문서 진행 중 확정)

결정 번호가 붙지는 않았지만 **뒤집으려면 근거가 필요한** 판단들이다.

| 판단 | 내용 | 근거 문서 |
|---|---|---|
| **대시보드 임베드 방식** | 전체 임베드 → 주제 버튼 + **"섹션만 보기" 모드**(A2a). 592px 칸에 1180px 대시보드가 안 맞아 가시성이 낮았다. 시각화를 **이중 관리하지 않는 것**이 핵심 이득 | [`CHANGELOG.md`](CHANGELOG.md) v0.3·v0.4 |
| **A3a 폐기** | 크로스오리진 `postMessage` 불필요 — 컨텍스트를 `{topic}` 단일 값으로 단순화했다 | [`specs/A-product-ux.md`](specs/A-product-ux.md) |
| **목표 감정 = "정직한 신뢰"** | 매출·유동인구가 없는 데이터로 확신을 연출하면 거짓말이 된다. 자신감이 아니라 "모르는 걸 모른다고 말하는 상대에게 느끼는 안심"을 목표로 한다 | [`design/emotional-design.md`](design/emotional-design.md) |
| **지역을 점수로 줄 세우지 않는다** | *"이 지역이 어떤 곳인가"* 를 합성 지표로 만들 때 **점수(성과)가 아니라 유형(묘사)** 으로 간다. 이유는 두 가지다. ① **브랜드** — "성과"는 좋고 나쁨을 말하는 단어인데 매출이 없어 그 판단을 할 수 없다. ② **데이터가 점수를 못 버틴다** — 밀도만 9.4~596.6으로 퍼져 있고 HHI는 절반이 0.04 폭, 잔존율은 절반이 3.4%p 폭에 몰려 있다. 단순 가중합은 사실상 밀도 하나짜리가 되고, 정규화하면 의미 없는 차이가 큰 격차로 부풀려진다. 중앙동(밀도 1위·잔존율 상위·업종 집중)은 어느 쪽으로 줄 세워도 틀린다 — 원도심이라 상주인구 나눗셈이 만든 값이기 때문이다 | [`specs/A-product-ux.md`](specs/A-product-ux.md) A26 · §분포 주의 |
| **대시보드는 소스, 우리 파일은 파생물** | 지표를 더 가져오는 것은 이중 관리가 아니다. `build_map_data.py`가 대시보드에서 추출하고 SHA256을 기록하므로 원본이 바뀌면 다시 돌리면 된다. 단 **지도로 그릴 수 있는 것만** 가져온다 — 시계열 선그래프·산점도는 임베드가 맞다 | [`specs/B-data.md`](specs/B-data.md) §자산 인벤토리 |
| **증감에 초록/빨강 금지** | 우리 데이터로는 증가가 좋은 일인지 판단할 수 없다(목동·대흥동 반례). 방향만 표시하는 중립 2색을 쓴다 | [`design/design-system.md`](design/design-system.md) 규칙 2 · A19 |
| **Secondary Goal = 원본 대시보드로의 이탈** | 보통 이탈은 나쁜 지표지만, "AI 설명 → 원본 검증"이 성립해야 우리 브랜드가 완성된다. 붙잡아두는 걸 목표로 삼지 않는다 | [`identity.md`](identity.md) |
| **그림자를 더하지 않는다** | 현재 전부 1px 라인 구분인데 이게 이미 `차분함`에 맞다. 유지를 **결정**으로 명문화 | [`design/design-system.md`](design/design-system.md) §3 |
| **임베드 패널 팔레트는 범위 밖** | 통일하려면 분석 저장소 수정이 필요하다. 다크는 유지하고 "데이터 뷰포트"로 액자화 | [`context.md`](context.md) 비범위 |
| **RAG는 리포트가 4,000자를 넘을 때** | B5는 지금 하면 손해다. 리포트가 1,810자라 통째로 넣어도 996토큰이고, 청크만 넣으면 캐시 프리픽스가 2,460자 → 650자로 줄어 **1,024토큰 임계 미달로 캐시가 0이 된다.** 순이득 약 180토큰에 지연·요금·섹션 누락 위험이 붙는다 | [`specs/B-data.md`](specs/B-data.md) §B5 |
| **프론트 에러 트래킹은 붙이지 않는다** | C7은 백엔드만 적용하고 프론트는 **안 하기로 결정한다**(2026-09-10). ① 이 페이지는 **빌드가 없어** 관측 스크립트를 번들에 섞을 수 없고, 통째로 하나 더 부르면 F2(LCP 713ms)와 정면으로 부딪힌다. ② 지도는 **외부 소스 0**을 원칙으로 만들었다 — 글리프 URL조차 쓰지 않으려고 라벨을 Marker로 그렸다. 관측 도구 하나 때문에 그 원칙을 깨면 남는 게 없다. ③ **진짜 오류는 API 경계에서 난다.** 거기는 C7 백엔드가 이미 잡는다. 프론트에서 더 잡히는 것은 대부분 확장 프로그램·브라우저 소음이다. ④ 표본이 없다 — 개인 포트폴리오라 오류율을 낼 트래픽이 안 나온다. **되살릴 조건**: 백엔드 로그로 설명되지 않는 화면 오류 신고가 실제로 들어올 때 | [`specs/C-reliability-ops.md`](specs/C-reliability-ops.md) C7 |
| **토큰은 잘라서가 아니라 배치로 줄인다** | 답변 상한을 500→900으로 **올리면서** 입력 비용을 줄였다. 리포트 본문(1,783자)을 잘라 주입하는 선택지도 있었지만 하지 않았다 — 사용자는 화면에 없는 주제도 자유롭게 묻고, 그때 "리포트에 없다"고 답하면 그건 절약이 아니라 품질 저하다. 대신 ① 프롬프트에서 **고정 블록을 전부 앞으로, 가변 블록을 전부 뒤로** 옮겨 자동 캐싱 프리픽스를 60자 → **2,432자(95%)** 로 키웠고 ② 무제한이던 대화 이력에 상한을 뒀다. 잘라야 할 것은 사용자에게 보이는 정보가 아니라 **매번 똑같이 다시 보내던 비용**이었다 | [`specs/C-reliability-ops.md`](specs/C-reliability-ops.md) · `chat_service.py` |

## 운영 제약 (협상 대상 아님)

- `firebase-service-account.json` · `.env`는 **gitignore 유지, 커밋 금지.** 값을 문서·로그·대화에 노출하지 않는다.
- **워밍업·상태 확인 목적으로 쓰기 요청을 폴링하지 않는다.** (과거 Firestore에 쓰레기 레코드가 쌓인 적 있음)
- 사용자에게 보이는 텍스트는 **한국어**로 쓴다 (저장소 루트 규칙).
- `main`은 배포 대상이다. 검증 전 실험은 별도 브랜치에서 한다.
