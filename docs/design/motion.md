# 마이크로 인터랙션 (Micro-interactions)

> **상위**: [문서 허브](../PORTFOLIO_SPEC.md) · **갱신**: 2026-09-08
> 성격: **구현 스펙.** A18(모션 원칙)·A21(대기 상태) 담당이 읽는다.

> **질문**: 움직임이 브랜드 경험을 어떻게 강화하는가?

---

## 출발점 — 현재 모션은 0이다

실측: `frontend/css/style.css`에 `transition` · `animation` · `@keyframes`가 **하나도 없다.**

그래서 이 문서의 과제는 **"모션을 줄이는 것"이 아니라 "어디에만 넣을지 정하는 것"** 이다. A18을 "모션 최소 원칙"이라 적었지만, 실제로는 **없는 상태에서 필요한 곳에만 더하는** 작업이다.

---

## 판단 기준

우리 브랜드는 `침착한 · 솔직한 · 정확한`이고 목표 감정은 **"정직한 신뢰"** 다. 사용자는 **저축을 걸 결정을 앞두고 불안한 상태**다.

여기서 모션의 채택 기준이 나온다.

> **정보를 전달하는 움직임만 넣는다. 기분을 만드는 움직임은 넣지 않는다.**

---

## 유형별 채택 판정

| 유형 | 목적 | 판정 | 이유 |
|---|---|---|---|
| **State Change** | 상태 전환 표시 | ✅ **최우선** | **우리가 가장 부족한 곳.** 43초 동안 아무 피드백이 없다 |
| **Feedback** | 액션 확인 | ✅ 채택 (최소) | 클릭이 먹었는지 몰라 두 번 누르는 것을 막는다 |
| **Navigation** | 화면 전환 가이드 | ⚠️ 모바일 탭만 | 데스크톱은 3분할 동시 표시라 전환 자체가 없다 |
| **Entrance** | 새 콘텐츠 주목 | ⚠️ 주제 패널 교체만 | 채팅은 계속 메시지가 붙는데 매번 등장 애니메이션이면 **소란스럽다** |
| **Delight** | 기억에 남는 순간 | ❌ **전면 배제** | 아래 참조 |

### Delight를 배제하는 이유

confetti·바운스 같은 축하 연출은 **이 서비스에서 조롱이 된다.**

사용자가 얻는 결과는 "여기 창업하면 성공한다"가 아니라 **"점포 수로 본 방향, 다만 매출은 모름"** 이다. 그 결과에 축하 애니메이션을 붙이면, 우리가 보증할 수 없는 것을 보증하는 것처럼 연출하는 셈이다. [`emotional-design.md`](emotional-design.md)에서 `에너지`·`플레이풀`을 배제한 것과 같은 논리다.

**리포트 생성 완료(Primary Goal 달성)에도 축하 연출을 넣지 않는다.** 조용히 결과를 내놓는 것이 이 브랜드의 완료 방식이다.

---

## 모션 스케일

일반 권장값(피드백 150~200ms / 전환 250~350ms / 등장 400~600ms + stagger)보다 **전반적으로 짧게** 잡는다. `차분함`은 느린 게 아니라 **눈에 안 띄는 것**이고, 등장 애니메이션과 stagger는 정보 밀도가 높은 3분할 화면에서 소음이 된다.

```
--motion-feedback   120ms  ease-out       버튼·칩 눌림, 호버
--motion-fade       150ms  ease-out       주제 패널 교체, 상태 오버레이
--motion-pane       200ms  ease-in-out    모바일 탭 전환
그 외              없음
stagger            사용하지 않음
```

## 인터랙션 정의

### 1. 주제 버튼 선택

```
Trigger:    주제 버튼 클릭
Animation:  border-color · background-color 전환
Duration:   120ms
Easing:     ease-out
Purpose:    선택이 먹었음을 알린다
금지:       scale·translate — 버튼이 움직이면 8개 그리드가 흔들려 보인다
```

### 2. 주제 상세 패널 교체

```
Trigger:    주제 변경 (다른 주제 선택)
Animation:  이전 내용 opacity 1→0 (150ms) → 새 내용 0→1 (150ms)
Duration:   150ms × 2
Easing:     ease-out
Purpose:    내용이 통째로 바뀌었음을 인지시킨다 (깜빡임 방지)
주의:       iframe은 페이드 대상에서 제외 — 리로드가 겹치면 두 번 깜빡인다
```

### 3. 대시보드 뷰포트 로딩

```
Trigger:    iframe src 설정
State:      오버레이 표시 → load 이벤트 → 오버레이 fade out 150ms
Timeout:    15초 → 에러 상태 + [다시 시도]
Purpose:    1.8MB 파일이라 즉시 안 뜨는 것이 정상임을 알린다
금지:       스피너 회전 애니메이션 — 정적 문구로 충분하다
```

### 4. 채팅 대기 상태 ★ 가장 중요

```
Trigger:    메시지 전송
현재:       "생각하는 중..." 정적 텍스트, 끝. 43초여도 그대로
문제:       사용자가 멈춘 줄 알고 새로고침하거나 떠난다
```

**단계적 문구** — 경과 시간을 **숨기지 않고 알려준다.** 정직한 신뢰 브랜드의 대기 상태 처리다.

| 경과 | 문구 |
|---|---|
| 0~5초 | `생각하는 중...` |
| 5초~ | `생각하는 중... (8초)` — 경과 초 표시 |
| 15초~ | `백엔드가 절전에서 깨어나는 중입니다. 최대 50초까지 걸릴 수 있어요. **요청은 계속 진행 중입니다.** (18초)` |

```
Animation:  없음 — 숫자만 갱신 (1초 간격)
Purpose:    진행 중임을 사실로 알린다. 애니메이션으로 "바쁜 척"하지 않는다
```

> **문구 정확성 문제** — 현재 `cold` 에러 메시지는 "잠시 후 **다시 시도해 주세요**"인데, 실제 콜드스타트에서는 **요청이 붙잡힌 채 자동 완료된다**(실측 43초). 재시도를 권하는 건 틀린 안내다. 대기 중 문구는 "**기다리면 됩니다**", 진짜 실패했을 때만 재시도를 권한다.

### 5. 답변 도착

```
Trigger:    응답 수신
Animation:  로딩 버블 텍스트를 답변으로 교체 (현재 방식 유지)
Duration:   없음
Purpose:    —
근거:       버블이 이미 있던 자리에 내용만 바뀌므로 등장 애니메이션이 불필요.
            새 요소를 만들어 slide-up 시키면 스크롤 위치가 튄다
```

### 6. 주제 구분선 삽입

```
Trigger:    대화 도중 주제 변경
Animation:  opacity 0→1, 150ms ease-out
Purpose:    대화 흐름에 끼어든 것이므로 최소한의 등장 신호는 준다
```

### 7. 모바일 탭 전환

```
Trigger:    하단 탭 클릭
Animation:  opacity 전환 200ms ease-in-out (슬라이드 아님)
Purpose:    어느 패널로 갔는지 인지
금지:       가로 슬라이드 — 세 패널이 형제 관계가 아니라 방향이 모호하다
```

### 8. 리포트 생성 완료

```
Trigger:    A14 리포트 4블록 렌더
Animation:  없음
Purpose:    —
근거:       Primary Goal 달성 지점이지만 축하하지 않는다. Delight 배제 원칙
```

## 접근성 — `prefers-reduced-motion`

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

**대기 상태의 경과 초 표시는 이 규칙의 영향을 받지 않는다.** 그건 애니메이션이 아니라 **정보**다. 줄이면 안 된다.
