## 1. Color System

### 역할별 팔레트

```
Primary        #1E478F  Trust Navy    핵심 액션 · 선택 상태 · 링크
Primary Hover  #2F5FA8
Primary Tint   #EEF3FB                선택 배경 · 컨텍스트 칩
Accent (Warm)  #FBF7F1  Warm Ivory    AI 버블 배경 ※ 채팅 칸 전용
Accent Line    #E6D9C6                AI 버블 경계
Canvas         #F6F7F9  Cool Gray     페이지 배경
Surface        #FFFFFF                패널 · 카드
Line           #E3E6EA                경계
Text Primary   #16191D  Ink 900       제목 · 핵심 수치
Text Body      #3B4252  Ink 700       본문
Text Muted     #6B7280  Ink 500       보조 · 메타
Caution        #8A5A00 / #FDF6E7      한계 고지 ※ 위험 아님, "읽어야 할 것"
Error          #B3261E / #FDECEA      요청 실패 · 삭제
Success        #1B7A4B                시스템 상태 전용 (저장 완료 등)
Viewport BG    #0F1319                임베드 대시보드 액자 (다크 유지)
```

### 규칙 1 — Primary 액션은 한 화면에 하나

현재 `#2563eb`가 버튼·선택·링크·유저 발화·활성 탭 **5가지를 겸하고 있다.** 파란색이 흔해지면 강조력을 잃는다.

역할을 세 갈래로 분해한다.

| 갈래 | 쓰는 것 | 개수 제한 |
|---|---|---|
| **액션** (누르면 뭔가 일어남) | Primary 배경 | **화면당 1개** — 나머지 버튼은 `Surface + Line` 중성 |
| **선택 상태** | Primary 배경 | 단일 선택이므로 자연히 1개 |
| **정체 표시** (누를 수 없음) | Primary 배경 | **제한 없음** |
| **링크** | Primary 텍스트 | 제한 없음 |

> **"정체 표시" 예외가 필요한 이유** — 사용자 발화 버블은 Primary 배경이지만 대화가 길어지면 화면에 여러 개가 쌓인다. 이건 규칙 위반이 아니다. **누를 수 있는 것이 아니라 "누가 한 말인지"를 나타내는 표시**라 액션 강조와 경쟁하지 않는다. 개수를 제한하면 대화 구분이 무너진다.
>
> 반대로 **주제 버튼(선택 상태)과 주변 액션 버튼이 동시에 Primary면 충돌한다.** 주제가 선택된 상태에서는 "이 주제로 AI에게 질문" 등 주변 버튼을 중성으로 내린다.

### 규칙 2 — 증감에 초록/빨강을 쓰지 않는다

```
Trend Up    #2F5FA8  (Cool)      증가
Trend Down  #B06A2C  (Warm)      감소
```

데이터 대시보드의 관습은 `증가=초록(좋음) / 감소=빨강(나쁨)`이다. **우리는 그 판단을 할 수 없다.** 점포가 늘어난 게 좋은 일인지 우리 데이터로는 모른다(매출 없음). 실제 반례가 있다.

> **목동**은 잔존율 최저(73.7%)인데 **+5.3% 늘었고**, **대흥동**은 밀도 2위인데 **+0.4%로 멈췄다.**

초록/빨강은 이 뉘앙스를 지워버린다. 그래서 **방향만 표시하고 가치는 매기지 않는 중립 2색**을 쓴다. 문구에서도 증감 옆에 "좋다/나쁘다" 어휘를 쓰지 않는다.

**이건 장식이 아니라 브랜드 약속의 시각적 구현이다.** (→ A19)

### 규칙 3 — 범주에는 순서 있는 색을 쓰지 않는다

```
Map Type 1  #2B6A94  진한 파랑   촘촘하고 자리잡은 곳
Map Type 2  #6B5AA6  진한 보라   촘촘하고 자주 바뀌는 곳
Map Type 3  #AFCEE0  연한 파랑   성기고 자리잡은 곳
Map Type 4  #C6BEDF  연한 보라   성기고 자주 바뀌는 곳
Map Type 5  #C9CED4  무채색      따로 봐야 하는 곳
```

지도 지표 5종은 순서 있는 값이라 한 색의 명도 램프(`--map-level-1~5`)를 쓴다. **A26 지역 유형은 순서가 없다.** 같은 램프를 쓰면 5번 칸이 1번 칸보다 "높은" 것처럼 읽히는데, 유형에는 높고 낮음이 없다.

그래서 **두 축을 두 속성에 나눠 넣는다** — 색상이 교체 축(파랑=자리잡음 / 보라=자주 바뀜), 명도가 밀도 축(진함=촘촘 / 연함=성김)이다. 범례를 안 봐도 같은 계열끼리 같은 성격이라는 게 읽힌다.

초록·빨강을 쓰지 않는 이유는 규칙 2와 같다. **`자주 바뀌는 곳`에 경고색(`--caution`)을 쓰지 않는 것도 같은 이유다** — 교체가 잦은 게 나쁜 일이라는 판단을 우리는 할 수 없다. 파랑과 보라는 둘 다 차갑고 어느 쪽도 경고로 읽히지 않는다.

3D 높이도 쓰지 않는다. 유형 번호를 높이로 세우면 4번이 1번보다 큰 값이라는 거짓말이 된다.

### 규칙 4 — 증감 지도는 발산형이다

```
Map Change 1  #B06A2C  감소 (= --trend-down 계열)
Map Change 2  #D8E4F5  0 ~ +1.4%
Map Change 3  #9DBBE4  +1.4 ~ +3.4%
Map Change 4  #5A88C4  +3.4 ~ +5.7%
Map Change 5  #2F5FA8  +5.7% 이상  (= --trend-up)
```

증감은 0을 기준으로 방향이 갈린다. 한 색 명도 램프를 쓰면 감소가 "가장 옅은 증가"처럼 읽힌다. **색상이 방향을, 명도가 크기를 맡는다.**

감소가 한 칸뿐인 이유는 데이터다 — 82개 중 **9개만 줄었다.** 더 쪼개면 칸마다 두세 개씩만 들어가 색이 정보를 잃는다.

색은 `--trend-down` / `--trend-up`과 같은 계열이라 규칙 2와 어긋나지 않는다. 초록·빨강을 쓰지 않는 이유도 같다 — **증가가 좋은 일인지 우리 데이터로는 모른다.**

3D 높이는 쓰지 않는다. 음수를 높이로 세울 수 없다(아래로 파인 건물은 없다).

> **범위 주의**: 분석 저장소 대시보드는 별도 팔레트다. 임베드 패널까지 통일하려면 분석 저장소 수정이 필요하므로 **범위 밖**. 다크 패널은 "데이터 뷰포트"로 액자화한다.

## 2. Typography

### 현재 상태 진단

`font-size` 값이 **11종**인데 전부 `0.72rem ~ 1.1rem`(11.5~17.6px) 안에 몰려 있다. **6px 범위에 11단계라 위계가 사실상 없다.**

- `h1`(17.6px)과 `h2`(15.2px)의 차이가 **2.4px**
- 화면의 주인공인 `.topic-headline`(`77,904 → 80,704개`, 16.8px)이 **`h1`보다 작다**

수치가 핵심인 서비스인데 수치가 가장 작게 그려져 있다.

### 목표 스케일

```
Headings / Body   Pretendard  (400 / 500 / 600)   ※ 700 남용 금지 — 차분함
Numerals          동일 서체 + font-variant-numeric: tabular-nums (전역)

Scale (1.25 ratio)
  Display   28px / 600   핵심 수치 헤드라인      ← 현재 16.8px
  H1        22px / 600   서비스 제목             ← 현재 17.6px
  H2        18px / 600   패널 제목               ← 현재 15.2px
  H3        16px / 500   소제목
  Body      15px / 400   본문 · 버블
  Caption   13px / 400   메타 · 토큰 · 각주
```

**세리프는 쓰지 않는다.** 감성 매트릭스의 `신뢰 = 안정적인 세리프/산세리프` 중 산세리프를 택한 이유는, 한국어 세리프(본명조 계열)가 소자 가독성이 떨어지고 무게감이 `차분함`을 넘어 `권위`로 가기 때문이다. **권위는 골목상권의 축이지 우리 축이 아니다.**

> **결함**: 현재 `font-family`에 `Pretendard`가 선언돼 있으나 `@font-face`도 CDN 링크도 없어 **맑은 고딕으로 폴백된다.** A16에서 실제 로드한다. → **해결됨** (`f1f5dff`)

### Display 단계가 앉을 자리 — 무대마다 하나씩

`Display 28px`는 **무대의 핵심 수치 한 곳**에만 쓴다. 장식용 큰 글자가 아니라 *"이 화면이 답하는 숫자"* 의 자리다.

| 무대 | Display가 앉는 곳 |
|---|---|
| 주제 상세 패널 | `.topic-headline` (`77,904 → 80,704개`) — 적용 완료 |
| **지도 무대** | **선택한 동의 지표 값** (`밀도 131.4`) — **미적용, A31** |

> **주의 — 이 규칙은 무대를 옮길 때 따라오지 않는다.** A15·A16은 주무대가 주제 패널일 때 검증돼 닫혔고, A22·A27이 주무대를 지도로 옮겼을 때 함께 이사하지 않았다. 결과적으로 지도 무대에서는 **가장 큰 글자가 앱 이름(22px)이고 데이터 최대치가 범례 13px**이다. 새 무대를 만들면 이 표에 줄을 추가하고 Display 자리를 정한다.

`tabular-nums`는 **전역**이다. 예외를 두지 않는다 — 범례처럼 숫자가 나란히 서는 곳에서 빠지면 자릿수가 흔들려 비교가 어려워진다.

## 3. Spacing · Radius · Shadow

```
Base unit    4px      스텝: 4 · 8 · 12 · 16 · 24 · 32
```

8px 배수만 쓰면 조밀한 3분할 UI에서 6·10·14px을 표현할 수 없어 **4px 기반**으로 잡는다. 현재 CSS는 `4/6/7/8/10/12/14/18/24px`이 규칙 없이 섞여 있다.

```
Radius
  버튼 · 입력      8px
  데이터 패널      10px    정돈 (신뢰)
  채팅 버블        16px    부드러움 (따뜻함)   ← 현재 12px
  칩 · 배지        999px
```

라운드로도 **감성 분업**(데이터=쿨 / 채팅=웜)을 표현한다.

```
Shadow
  평면 요소   그림자 없음 — 1px Line으로만 구분
  떠 있는 것  모달 · 드롭다운에만  0 4px 16px rgba(22,25,29,.10)
```

현재 화면은 `box-shadow`가 사실상 없고 전부 보더로 구분한다. **이건 이미 `차분함`에 맞으므로 유지하고 원칙으로 명문화한다.** 그림자를 더하는 방향이 아니라, **더하지 않기로 결정한다.**

```
Motion
  주제 전환   150ms ease  fade
  그 외       없음
  prefers-reduced-motion: reduce  →  전부 제거
```

## 4. 구현 참고 — 토큰 정의


## 5. 다크 모드 (A32)

> 성격: **미구현 스펙.** 값은 **제안이며 측정 전이다** — 아래 §검증 없이 그대로 쓰지 않는다.

### 왜 토큰 교체로 끝나는가

A15가 색 리터럴을 전부 `:root`로 몰아넣었다. 현재 **색 토큰 43개, `:root` 밖 리터럴 0개**이고 JS·HTML에도 없다 — `map.js`는 `getComputedStyle`로 읽는다. 그래서 `@media (prefers-color-scheme: dark)` 한 블록에서 같은 이름을 재정의하면 화면 전체가 따라온다.

**토글은 만들지 않는다.** 헤더에 버튼이 셋이고 390px에서 제목을 말줄임해야 겨우 들어간다(A30 실측). 넷째는 안 들어가고, OS 설정을 존중하는 편이 저장할 상태도 안 늘린다.

`:root`에 **`color-scheme: light dark`** 를 함께 선언한다. 없으면 `<select>` 5개와 스크롤바가 밝게 남는다.

### 그냥 뒤집으면 깨지는 것

| | 문제 | 처리 |
|---|---|---|
| **지도 램프** | 지금은 **값이 클수록 어둡다**(`#D7E7F0` → `#163E65`). 어두운 배경에 그대로 두면 최고값이 배경으로 가라앉아 **읽기가 뒤집힌다** | **반전이 아니라 방향 재설정.** 다크에서는 값이 클수록 **밝다** |
| **범주 팔레트(A26)** | 색상이 축(파랑=자리잡음/보라=자주 바뀜), **밝기가 밀도**다. 라이트에서는 `촘촘함 = 어두움` | 다크에서는 `촘촘함 = 밝음`. **색상 축은 그대로** |
| **`map.js`** | `const colors = ramp("level")` — 색을 **시작할 때 한 번만** 읽는다. 테마가 도중에 바뀌면 지도만 옛 색으로 남는다 | `matchMedia("(prefers-color-scheme: dark)")` 변경 시 램프를 다시 읽고 레이어를 다시 칠한다 |
| **임베드 액자** | `--viewport-bg #0F1319`는 **밝은 페이지 위의 다크 액자**라서 "데이터 뷰포트"로 읽혔다. 다크에서는 배경과 붙는다 | 배경은 그대로 두고 **테두리로 액자를 유지** |
| **플로팅 패널** | `--shadow-float`가 다크에서 안 보인다. A30 패널과 사이드 패널이 배경에 잠긴다 | **테두리로 대신한다.** §3의 "그림자를 더하지 않는다"와 어긋나지 않는다 |
